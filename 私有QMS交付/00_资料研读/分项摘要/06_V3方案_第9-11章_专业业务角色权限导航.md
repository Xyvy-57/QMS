## 1. 核心摘要

V3 方案第 9–11 章（p24–38）覆盖专业质量业务、角色权限和导航组织三部分。

第 9 章规定 CAPA/8D、客诉、供应商质量、计量与 MSA、SPC 与过程能力、审核/管理评审/文件/培训、FMEA 与控制计划的当前承载范围。核心原则是事实、本次处置、长期验证和关闭分开记录，一个对象完成不自动关闭其他对象：CAPA 不是每张 NCR 的必附单据，实施完成不等于有效；客户资料提交不等于客户批准；供方回复和验证追加在原 NCR 上，不另建 SCAR；校准合格不等于测量系统适用，恢复使用不追认历史测量；SPC 和 Cpk 都不能放行批次。本轮明确纳入 MSA 首个方法"平衡交叉型 Gage R&R"和基于真实本地实测的 I-MR；准入、综合评分、独立 SCAR、供方门户、DOE、APQP/PPAP、结构化 FMEA、完整管理评审不纳入或列为候选。

第 10 章规定服务端按"动作 + 对象 + 当前版本 + 证据"授权，superuser 不自动获得质量批准权；专项资格、独立签审、委托、限额、岗位任命只在企业有明确依据时配置，未配置的人工批准返回"待配置"；六种演示身份只是待确认示例。

第 11 章用 10 个导航分组、29 个稳定入口组织 53 个工作面；编辑、比较、审批须先选定对象；菜单可见不代表有权限；155 项来源和 8 项候选保持可追溯。

#### 9.1 CAPA 与 8D（p24）

| 主题 | 原文要点 | 出处 |
|---|---|---|
| 定位 | CAPA 处理系统性原因和防再发，**不是每一条 NCR 都必须附带的单据** | p24 |
| 触发策略 | 按严重度、重复发生、客户要求、审核发现、过程失控和风险决定；**不升级时要记录理由** | p24 |
| 多对一 | 多个 NCR 可以关联同一个 CAPA；不能把重复问题重新建单，否则会丢失趋势 | p24 |
| 8D 定位 | 8D 是 CAPA 的一种组织方式。D0 是可选的启动阶段，单独显示；D1–D8 的阶段名称和所用方法的修订版是固定的；不同企业的模板差异通过版本来配置；**不能用"八个页签都勾满"来判断有效** | p24 |
| 根因与措施 | 根因要区分**发生原因**和**逃逸原因**，并关联验证证据；纠正措施必须对应到原因；**实施完成和有效性验证分开** | p24 |
| 有效性计划 | 在实施前明确 6 项：观察窗口、产品/工序范围、数据来源、目标、验证责任、失败回退 | p24 |

| 不能关闭 CAPA 的情形 | 观察期未到、数据不足、验证失败、标准化未完成 | p24 |
| 重开 | 验证失败重开时，保留之前的判断记录 | p24 |

#### 9.3 供应商资料、来料质量与整改跟踪（p25–27；业务图10）

**（1）四项工作**（p25）：① 维护供方基本资料；② 联查该供方真实的 IQC 来料批次和检验结果；③ 从已知不符合追溯到原任务、轮次和 NCR；④ 在原 NCR 中记录供方回复和验证，必要时复用 CAPA/8D。

**（2）供应商资料规则**（p25）
- 可以正常新建、编辑；**代码唯一**；联系人、电话、邮箱、描述按已有资料填写；关联产品必须引用系统中实际已建的产品。
- 基本资料**不代表质量准入已批准，也不代表供货受限**。
- IQC 建单时，供应商从预先维护的供应商资料主账中选择。如果缺少这个供方，可以就地新增，保存后回到原任务草稿并选中新供方；取消也回到原草稿，产品、方案、批次和数量都保留。
- 历史上没有关联供方的记录，保留为"未知"。当前没有接 ERP：不假设供应商会自动出现，也不因此新增 ERP 导入建设。

**（4）统计口径**（p25–26 跨页表格，已按原页还原）
总原则：直接读取已关联供方的实际批次、任务、轮次、样本和可采纳读数。已知问题取**任何一轮真实 IQC** 中的有效不符合，复检通过也不抹掉原问题；样本符合率**只用原轮**；各项的分母、统计范围以及"不能据此推定的结论"分别表达。

| 指标 | 来源与分母 | 不能推定的结果 |
|---|---|---|
| 完成原检批次 | 同一批次的所有原 IQC 任务都技术完整且已提交，按 batchId 去重 | 不能用同批中一项任务完成代替全部原检完成，也不表示整批已接受 |
| 问题批次占比 | 完成原检批次中有已知有效不符合的批次数 ÷ 完成原检批次数 | 普通 measurement 不符合不当作整批拒收；分母为零时不显示 0% |
| 全部已知问题与待检 | 未完整检验但已知有问题的批次另列，待检情况单独说明 | 不把未完整的问题混进完成批次的比例，也不因复检通过而清除问题 |
| 完整样本符合率 | 原轮中某个样本的全部必测项都已采纳，就可进入样本分母；按 sampleUnit 分别计算 | 不要求其他样本或整个任务已提交；读数行数不能当作实体数；单位混杂时汇总率不可计算 |
| 主要不符合要求 | 按同批、实际 sampleId、稳定的 characteristicId 和单位去重，同一实体重复复检失败只计一次 | 新取样的样本各自保留事实；不因对同一实体反复复检而放大问题数 |

**（5）供应商对比与筛选**（p26）
- 对比依据：同一范围内的实际问题批次、完成分母和未完备情况。主要问题、最近问题记录日、未关闭 NCR、逾期跟进和责任人都从真实来源汇总；**不生成质量、交付、服务综合分**。
- 最近问题记录日取可采纳失败记录的 recordedAt（本地日期）；缺失就标"未知"，不用到料日代替。同一实体的复检失败去重，但保留最近的记录日。
- 没有关联供方的数据单独列出；旧的无供方关联资料不并入任何一家供方的指标。
- 产品、供方、来料日期的筛选，与批次、项目、月份趋势的下钻**共用同一个范围**；月份按来料日期归期。
- 日期取值顺序：优先 receivedAt；缺失时用可证明的批次 createdAt（本地日期）并注明来源。两者都缺的历史数据：不筛日期时保留为"日期未明确"；有 from/to 筛选时排除，并提示 excludedUndatedBatches。
- 非法筛选返回明确的错误，不悄悄扩大范围。

**（6）整改跟踪**（p26）
- 在**原 NCR** 上追加跟进安排、供方回复和验证记录，保留内容、证据、实际处理人身份和日期。
- 跟进安排要明确责任人 owner，可填写回复期限 dueAt 并提示逾期。**登记回复之前不强制要求先有安排。**
- 追加新安排后，必须用这之后的新回复和新验证来判断当前进展，原记录保留。验证引用**最新的回复**；补充了新回复，旧验证就过期。
- "待回复 / 待验证 / 验证未通过 / 已验证"只表示本项跟踪的状态，**不会自动关闭 NCR、CAPA 或 Hold**。
- CAPA/8D 通过 sourceNcrId 引用同一个问题；**不建立独立的 SCAR 编号、阶段、审批或关闭链**。

**（7）批次明细溯源**（p26）：保留 originalRoundId 和原检报告的直达链接，并列出 failedRoundIds 对应的实际失败轮次报告；不用当前活动轮代替原轮或问题轮。即使出现"原检通过 → 后续某轮失败 → 再次复检通过"，也能准确追到计入问题统计的那次失败。

#### 9.4 计量与测量系统（p27–28；业务图11、图12）

**（1）量具管理**（p27）
- 以下 7 类信息分别管理：量具类型目录、实体计量资产、校准技术结论、有效区间、用途能力、位置借用、维修状态。
- 原文举例：一件器具可能借出了但校准仍有效；也可能校准日期没到，但已经损坏或失准。
- **判定"可用"必须同时满足四个条件：用途、状态、范围、资格**；不能只看下次校准日期。

**（2）校准记录要素**（p27）：As Found 与 As Left、标准器及其资格、证书、误差/不确定度、方法、环境、执行与复核。

**（3）失准影响评估**（p27）：校准失败或出现异常时触发 → 确定可能的失准起点及依据 → 反查这件量具的使用记录 → 评估这些测量还能否采纳 → 按产品风险决定重检、Hold 或客户措施。如果无法精确确定起点，就明确写出不确定的范围，由合格人员决策；**不能自动把最近一次校准合格的日期当作已证实的失准起点**。

**（4）恢复使用**（p27）：这是面向未来的决定，要求维修以及必要的校准和用途评审都已完成。**恢复使用不能追认过去的测量，也不会自动解除产品 Hold。**
**（5）校准延期**（p27）：不能只靠修改计划日期来延长资格；确实需要延长时，必须有独立依据和适用的批准。

**（6）MSA 范围**（p27，[S05]）
- 原文："MSA 本轮是明确业务范围"。可以从正常入口建立研究，引用量具档案以及适用的产品/特性，明确零件、操作者和重复测量的安排，录入研究读数并分析。
- 普通检验的样本矩阵和 MSA 研究矩阵**分开保存**；不能把"多件各测一次"的检验自动当作重复性与再现性研究。
- 校准合格 ≠ 测量系统适用于本用途；MSA 结果也不延长器具的校准期限。

**（7）首个方法：平衡交叉型 Gage R&R**（p27–28，[S13]）

| 项目 | 规则 |
|---|---|
| 模型 | 两随机因素 ANOVA，保留零件、操作者和交互项；**不根据显著性自动合并交互项** |
| 设计参数 | 零件数、操作者数、重复次数都由用户明确指定。**至少 2×2×2** 是估计所需方差分量的最低结构条件，**不是推荐样本量，也不是企业标准**（图12 另注"不预设固定 10/3/2 安排"） |
| 平衡性 | 每个零件由每个操作者测量相同次数；出现缺格、身份重复、非数值或单位不一致时，不能形成完整分析 |
| 前提检查 | 检查交叉设计、残差等适用前提；结果只在该研究条件下解释 |
| 输出 | 重复性、操作者、交互、零件各分量和总变差，GRR 及各项 %StudyVar；保留原始读数和方法版本 |
| 异常处理 | 矩估计得到负方差时，同时显示原估计值、按 0 参与计算的处理和警告；总变差为 0 时百分比不可计算 |
| 判定 | **不给出臆定的 10%/30% 企业判据**；不自动批准量具或产品 |
| 其他方法 | 偏倚、线性、稳定性、属性一致性等方法只保留概念与资料，须另按实际需求选择；**不自动扩建成完整方法族** |

#### 9.5 SPC 与过程能力（p28；图12）

**（1）数据来源规则**（p28）
- 用户明确选择**产品、方案修订和特性**；使用任务实际采用的要求，以及同单位、来源可核实的已保存实测点；不混用其他图版、方案快照或单位。
- 每个点都能回查到任务、轮次、实体样本和读数来源。真实的超差值也纳入所选数据，不为了曲线好看而删掉。
- 原生来源中还没有完成可证明映射的数据，不得与本地读数混算。

**（2）I-MR 方法**（p28，[S12]）

| 项目 | 原文规则 |
|---|---|
| 移动极差 | 按保存的数据点清单及其顺序，计算相邻两点的移动极差 |
| 组内标准差估计 | σ̂ = MR 均值 / 1.128 |
| I 图控制限 | 均值 ± 3σ̂（【推断】数学上等价于均值 ± 2.66 × MR 均值） |
| MR 图控制限 | 0 至 3.267 × MR 均值 |
| 规格限与控制限 | 规格限来自技术要求，控制限来自分析数据，**两者分开显示** |
| 信号 | 原文"当前信号只表达点超限"（【推断】指单点超出控制限；未包含其他判异规则） |
| 异常数据 | 数据不足、数据全为常数或无法计算时如实显示，不用固定的示意曲线代替分析结果 |

**（3）当前实现与生产要求**（p28）
- 当前本地原型：保存产品、方案修订、特性和点 ID 的选择，每次按当前可采纳的原始值重算。草稿读数在同一 ID 下修改后，结果可能随之变化；**目前还没有保存固定的结果快照或方法版本**。
- 生产实现应另外保存：原始值快照、点的顺序、方法/计算版本以及结果修订，以便结果可以复现。
- 持续监控基线、反应计划和更多图型"须逐步实现"。信号可以引出问题调查；是否停机或限制由明确的风险动作决定，**不一律等同于产品不合格**。

**（4）过程能力**（p28，[S04]）
- 区分短期估计和总体估计；要披露数据量、稳定性、分布假设、估计方法、置信区间或不确定性，以及用途。
- 样本不足或前提不满足时显示限制；**不能因为 Cpk 高就自动放行具体批次**。
- 不同图版、单位、工序以及返工前后的数据，不能不加说明地混算。
- 能力分析工作面必须明确选择本地方案及其中的特性；没选时保持"待选择"，不自动取第一份方案或第一项特性作为分析对象。
- 检验数据分析只使用能证明归属的数据；过程能力的完整假设和方法另行校验；不能凭一张曲线或一个指数就宣称通过了生产统计算法验收。

**（5）DOE**（p28）：DOE 和 SPC 是不同的概念。当前不建设试验设计、因子水平、优化推荐和确认试验流程，详见候选附录（V3方案 p2 称"第17 章候选附录"，范围外【交叉参考】）。

**（6）图12《MSA、SPC 与质量改进》**（p29 有图，与业务图12 一致）
- 副标题：MSA 专用的重复研究和普通检验数据分开管理；本轮支持交叉 Gage R&R 和基于真实本地实测的 I-MR。

### 2.2 第10章 角色与权限管理（p31–36）

#### 10.1 授权判定（p31）
1. 复用现有的账号、会话、接口权限和对象访问范围。
2. 由**服务端**核验动作、对象、当前版本和必要证据；列表、详情、附件、导出和原生工作台的判定保持一致。
3. 技术管理员不会因为是 superuser 就自动获得新增的质量批准权。
4. 签审必须绑定确定的内容；原值和原失败不能被任何权限角色覆盖。
5. 专项资格、同一自然人多账号识别、独立签审、委托、限额和岗位任命都属于**企业动作策略**，只有明确配置后才校验。
6. 需要人工批准的动作如果没有配置，就**返回"待配置"，不默认批准**；普通合格的完成流程也不会因此多出人工步骤。
7. 业务始终按单一企业使用，**不设多工厂选择器**。

#### 10.4 现有权限的增量接入（p34）
- 新增的质量动作复用 IAM，在服务层做明确的动作和对象校验；superuser **不能直接绕过**。
- 先盘点现有角色和待办，再按确认结果配置；**不能把所有存量管理员自动映射成批准人**；本轮也不强制新建自然人、资格、授权和委托子系统。
- 搜索没有命中时就返回空；导出在**创建、执行和下载三个环节都重新校验**权限。
- 需要能立即撤权的文件，通过**鉴权下载代理**提供；长效签名 URL 存在撤销窗口期，不能声称可以即时收回。
- 审计记录包括：服务器认定的操作者、对象版本、动作、原因、结果、发生时间/录入时间；策略要求时，再附上相应的任命、资格或委托快照。客户端填报的内容不能冒充服务器签署。
- 基础设施层面的特权，通过现有的最小权限、备份和维护审计来管理；应用层策略**不承诺能阻止任意的直接改库**。

#### 10.5 原型中的职责与操作边界（p35–36）
- 原型把职责视角和正式授权**分开表达**。职责视角用于看清同一个业务对象在编制、执行、处理、审查和系统管理之间如何分工；切换视角**不会**创建用户、岗位任命、签名或批准，也不会改变事实、任务状态或已记录的处理人（p35）。
- 页面以当前岗位、可办理的动作、具体对象、采用的版本和必要状态为主；详细的责任、输入输出和上下游矩阵放在方案和功能目录里（p35）。
- 操作同时受**职责合同和对象上下文**控制。职责不匹配或动作暂不可用时，在具体动作的位置说明原因；不能靠隐藏按钮假装做到了授权隔离，也不把职责/实现状态的说明铺满产品主界面。技术管理职责不隐含质量编制、采集、处置或批准权（p35）。
- 本地原型对保存、采集、建单、分析、问题处理和明确限制等已有命令做职责检查；原生编辑工作台只有在对应职责下才进入可写路径。资料预览中不允许仅凭切换角色就写成已批准、已验效或已关闭。没有企业签审策略和身份源的动作，保留设计和"待配置"状态，不生成演示批准人冒充正式签署；普通合格检验仍按现有明确规则完成，不为了凑齐角色而增加人工审批（p36）。
- **六种既有演示身份**及其动作映射属于待确认的示例配置，不是企业的岗位制度。原先"只有质量工程师能建单、只有检验员能录数"的限制没有用户需求依据，不能成为正常开检必须换人的理由。当前示例中：质量工程师可以维护标准、开检和录数；检验员可以从已有方案开检和录数；没有新增岗位。标准维护、开检、实测和结果记录，可以由具备相应动作权限的**同一个使用者连续完成**；是否需要职责分离，只按已明确的具体制度配置（p36）。
- 报告复核和 Hold 解除仍要核对各对象上明确的名单和证据；管理员和仓库身份不会因为技术权限而获得质量写入权。具体的演示动作矩阵由同一份责任合同生成，放在功能目录中（p36）。
- 首页汇总的是"当前空间检验任务"。派工功能还没有接通，所以不把空间内的全部任务说成当前用户的任务（p36）。
- 本地报告的处理方式由表单显式选择：直接汇总真实事实，或者按本次勾选的演示职责进行复核。只有选择复核时才使用这份名单；名单为空时不能提交需要复核的报告。本地的独立复核会校验所选演示身份与提交人身份不同，但这条演示规则不外推为企业统一的双人制度（p36）。
- 每条 Hold 可以单独选择本地解除名单；没有名单就不能解除；解除时必须提交证据说明。复核和解除都只影响对应的本地记录，不授予生产权限，不虚构正式签名，也不自动放开其他限制（p36）。
- 责任合同和导航合同**分开维护**：导航里的层级角色描述的是入口、详情或视图；业务职责描述的是谁对哪项结果负责，两者不能混用。业务动作遵循同一份责任定义，详细分工可在文档中查到，界面上不再逐页重复这张矩阵（p36）。
- 53 个工作面和 155 项原始来源保持可追溯。MSA 和真实数据分析在本轮的更新，依据的是用户 2026 年 11 月 15 日的明确要求，因此不能再用旧的"仅资料"限制把它们排除；同时也不增加外部账号或组织治理平台（p36）。

六种演示身份的名称在 p24–38 中没有列出，取自 V3目录 p3–4【交叉参考】：检验员、质量工程师、质量负责人、生产主管、仓库执行人、系统管理员（详见第 5 节）。

#### 图14《工作职责与质量事实交接》（p32）
- 副标题：分清结果责任和事实交接；岗位与动作的映射只是待确认示例，不是企业既定的岗位制度。
- 上排三项职责：编制职责（场景定义/标准版本；方案确定引用和项目；新版本不回写历史任务）→ 检验执行职责（任务/轮次/样本；形成真实读数及来源；采集不等于签审）→ 问题处理职责（事实/明确范围；形成本次处置与凭据；NCR、Hold 与复检各自记录）。

- 下排三项职责：审查职责（核对所选内容与证据；未配置策略不产生批准；失败报告不被改写为合格）；专业与体系职责（供方/计量/统计；审核/文件/培训；只读资料不冒充实施完成）；系统管理职责（账号与技术配置；不自动取得质量业务权；不代签、不改原值）。

#### 图15《权限判定与显式签审策略》（p35）
- 副标题：本地原型检查职责和可执行动作；生产环境仍须由服务端统一核验，不能用切换职责代替正式授权。
- 五步依次检查：① 身份会话（账号和当前会话有效；本地演示身份不等于生产授权）→ ② 职责与动作权限（查看/采集/评审/导出分开；系统管理不默认授予业务权）→ ③ 对象范围（产品族/批次/供方/具体案件；只能访问已授权的对象）→ ④ 已明确的签审策略（普通事实汇总不强制独立评审；只有显式选择独审时才检查评审人）→ ⑤ 当前状态与限制（确定轮次/修订，以及范围与动作的交集；解除限制缺少策略时为待明确）→ 全部通过（"适用检查通过"）→ 允许本次动作并留痕（绑定当前对象范围；事实汇总不代表生产批准）。
- 任何一步不通过时"返回具体原因"→ 拒绝本次越界动作（说明具体对象和缺项；保留已有事实与历史；不猜测未配置的权力；正常取证仍按明确权限）。
- 旁注框"一致覆盖业务入口"：列表/详情/附件/导出；原生写入口检查职责；生产环境须由服务端重验。

#### 11.3 场景及完整工作路径（p38）
- IQC、生产首件、IPQC、FQC 和 OQC 保留第 4.2 节（标题"不同检验类型的业务差异"，V3方案 p9，范围外【交叉参考】）中规定的不同对象、触发、输入和结果用途，各有独立的侧栏入口和场景内建单。
- P11 检验任务总览用于跨场景检索和统一安排，**不取代五类入口**；各入口继续共用任务、轮次、样本和证据模型。
- CMM 导入是一种采集方式；复检是有原因的新一轮；报告是固定下来的证据表达。
- 普通合格按策略完成；NCR 不自动限制整批；对子集复检不形成整批接受。
- 用户在任何工作面上都能回答六个问题：对象是谁、采用哪版依据、需要做什么、为什么受限、由谁负责、成功后改变哪个状态。缺项时列出具体证据和补齐入口；保存、提交、批准、撤销和实际执行分别表达；失败时保留输入；冲突时提供比较和重新加载；不能用一个笼统的"成功"掩盖部分失败。
- 多个产品、图版、批次和任务可以并行处理。上下文携带明确的对象 ID；原生图纸工作台未保存时，使用已有的"离开握手"；**禁止用全局"当前产品"，以免串单**。
- 批量操作显示范围和逐项结果；敏感批准在没有展示对象差异时不得盲批。

#### 11.4 追溯与实施边界（p38）
- **统一导航合同**为每个工作面保存：所属分组、稳定入口、角色、质量作用、生命周期位置、进入路径、是否需要先选对象。原型和功能目录读取同一份合同，避免两套菜单映射逐渐不一致。

## 6. 与"工业图纸气泡识别"的关联点

第 9–11 章本身不讲气泡识别算法，但有多处规则直接约束"图纸 → 特性 → 检验 → 分析/改进"这条链路。下表左两列是原文，右列是对"以气泡识别为检验标准源头的私有 QMS"的含义，全部属于【推断】。

| # | 原文关联点 | 出处 | 对气泡识别型私有 QMS 的含义【推断】 |
|---|---|---|---|
| 1 | "质量策划"分组的稳定入口是"图纸与气泡标注"（P02），对象内能力是"气泡和手录两来源形成检验要求"；内部工作面有"气泡特性编辑"（P03）、"图纸版本对比"（P04） | p37；V3目录 p2；业务图17 | 气泡识别结果是检验要求的两个来源之一（另一个是手录），应放在"质量策划"域，并通过"标准版本"进入方案。手录必须作为识别失败或无图纸时的并行来源 |
| 2 | "图纸与气泡标注 → 选定修订"：比较必须选择已有的修订，不能凭名称相同推断是同一对象；没有可比版本时明确说明，不伪造比较 | 业务图17；p38 | 图纸改版后重新识别、新旧气泡对比，都必须基于明确的图纸修订身份，不能按文件名或图号匹配 |
| 3 | 受控文件的红线对比只表达确定版本之间的差异；"**自动识别结果需标识算法及人工确认**"；"对比完成"不等于"影响评估完成" | p29 | 可以直接推及气泡自动识别：每条识别结果要记录算法/模型版本，并有人工确认状态；识别或比对完成，不代表已完成对方案和在途任务的影响评估 |
| 4 | 工程图纸和结构化方案通过**引用**集成，不能再复制技术要求形成另一个批准来源 | p29 | 气泡提取出的尺寸和公差应只有一个权威来源（标准版本），方案和报告只引用，不复制可编辑的副本 |
| 5 | 来料统计按"稳定 characteristicId"去重；P29 支持"检验项目"维度 | p26、p25 | 每个气泡对应的特性需要跨轮次、跨任务保持稳定 ID，否则统计、追溯和去重都会失效。图纸改版后特性 ID 如何延续，原文本段未给出规则 |
| 6 | SPC 要明确选择产品、方案修订和特性；**规格限来自技术要求**；不混用其他图版；控制限和规格限分开显示 | p28 | 气泡识别出的公差就是 SPC 规格限的来源；SPC 数据要按图纸修订/方案修订分区，识别结果改版后不能与旧图版数据不加说明地混算 |
| 7 | 过程能力：不同图版、单位、工序和返工前后的数据不能不加说明地混算；能力分析必须选定方案及其中的特性 | p28 | 同 #6；能力分析对象是"方案中的特性"，即源于气泡的检验项 |
| 8 | MSA 研究引用"适用产品/特性" | p27 | MSA 可以关联到具体的气泡特性（例如关键尺寸），以评估测量系统对该特性是否适用 |
| 9 | CAPA 标准化回流到"图纸、方案、SIP、培训……的相应修订"；图12"方案修订与采用 → 新任务采用改进后的受控版本" | p24；p29 图12 | 改进闭环最终会触发标准版本或方案修订，可能需要重新标注气泡或调整特性；旧任务继续绑定旧版本 |
| 10 | 编制职责："场景定义/标准版本；方案确定引用和项目；**新版本不回写历史任务**" | p32 图14 | 重新识别得到的新标准版本不能改写已开检任务的依据 |

## 7. 对私有QMS的可借鉴点，以及约束/边界

### 7.1 可借鉴的设计原则与机制（原文依据 + 【推断】的借鉴理由）
1. **对象各自闭环**：NCR、CAPA、客诉、Hold、整改跟踪、审核发现项各有关闭条件，互不连带（p25、p26、p29）。借鉴：状态机按对象独立设计，避免"一键全关"【推断】。
2. **实施与验证分离、以最新验证为准**：CAPA 结案不能用更早的"有效"覆盖最新的失败（p24）；整改验证绑定最新回复（p26）。
3. **不另起第二套单据**：供方回复/验证挂在原 NCR 上，CAPA/8D 用 sourceNcrId 引用，不建 SCAR（p26）。对小团队，单据数量少、追溯链短【推断】。
4. **统计口径显式化**：每个指标都写明"来源与分母"和"不能推定的结果"（p25–26 表）；零分母不显示 0%，单位混杂不汇总，未知日期单独处理（p26）。适合直接写进 PRD 的指标定义模板【推断】。
5. **原始轮与失败轮可追溯**：originalRoundId / failedRoundIds，复检不抹掉原问题（p26）。
6. **量具"可用"多条件判定 + 失准双闭环**：未来资格与历史影响分开结案（p27；业务图11）。
7. **MSA 与检验数据分开**：研究矩阵单独保存；先只做一个方法（交叉 Gage R&R），不预设判据（p27–28）。
8. **SPC 诚实呈现**：超差点不删；数据不足不画假图；规格限与控制限分开；生产环境保存快照以便复现（p28）。
9. **能力指标不放行批次**；SPC 正常不能替代合格判定（p28；图12）。
10. **服务端统一授权 + "待配置"返回**：未配置的审批不默认通过，也不给普通合格流程加人工步骤（p31）。
11. **两层策略表**："所有实现必须保持"与"有依据时才启用"分开（p33–34），可以作为私有 QMS 权限需求的骨架【推断】。
12. **同一使用者可连续完成主路径**，不强迫换人；职责分离只按企业明确的制度配置（p36；图14）。适合小团队【推断】。
13. **导出三处重验、鉴权下载代理、服务端审计**（p34）。
14. **三层导航（分组 → 稳定入口 → 对象工作面）**，加上"先选对象再编辑/比较/审批"（p37–38），以及导航合同与责任合同分开维护（p36、p38）。
15. **工作面"六问"**与部分失败逐项反馈（p38），可作为设计稿的验收检查表【推断】。
16. **自动识别结果标明算法并经人工确认**（p29），可直接迁移到气泡识别结果的可信度管理【推断】。

### 7.5 对私有 QMS 的约束提示【推断】
- 若照搬 V3 的"不纳入"清单，私有 QMS 一期不会包含供方门户、综合评分、SCAR、APQP/PPAP、DOE、完整管理评审。这些在云质等商用 QMS 中可能是标准能力，取舍需要在需求分析阶段单独确认，不能直接把 V3 的边界当成用户需求。

- 角色与审批规则大量依赖"企业依据"。私有 QMS 的目标客户（使用气泡识别服务的制造企业）的制度差异，需要通过可配置策略吸收，不应硬编码岗位。
