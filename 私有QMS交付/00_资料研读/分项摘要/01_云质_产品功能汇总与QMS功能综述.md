## 1. 核心摘要

云质产品功能汇总（2022-06-15，外部商用资料）的"中文""Eng"两个 Sheet 各列 29 个模块，两版逐行对应但非逐字互译。

本摘要将 29 个模块归为 9 个能力域：检验 6（来料/过程/最终/出货/周期性试验/检验规则）、不合格 2、问题与改进 4、供应商 2、计量 1、体系 3、分析看板 1、任务协同 3、平台能力 7（自定义字段、系统对接、登录、数据录入、语言、部署、数据安全）。

中英差异：
- **仅英文版**：AQL/Fixed/Percentage 抽样、OQC 自动生成 COC、车间大屏每 5 分钟刷新、RoHS 等。
- **仅中文版**：检验任务分配、合单/拆单、进度升级，可扩展越南语等。
- **口径不一**："最多 80 个报表"中文按"每个客户"，英文按"each user"。

e-works 文章（作者元数据 YunQuality）从管理诉求出发给出通用框架，共 10 个节号（"4."重复，实为 11 节）：质量统计分析（5 类场景）、检验规则与执行（各 7 条）、不合格品、供应商协同、客诉、CAPA、评审、问题、量具、项目、全景追溯。

**判断**：两份资料均无图纸识别、气泡标注、OCR/CAD 解析或特性自动提取能力。"检验规则（Inspection Plan）"只是检验方法、检验内容、缺陷描述等检验标准的统一与标准化管理；图纸仅作为存储文档和检验时的查阅资料出现。EW 中"哪个尺寸""关键特性测量值波动""贴近下公差线"等诉求，是气泡特性清单可支撑的下游场景【推断】。

### 2.9 EW §2 检验管理

**§2.1 检验规则标准**（L25–L32）

| 条 | 要点 | 出处 |
|---|---|---|
| 1） | 检验类型很多：来料检、生产自检、首检、巡检、末检、入库检、发货检、退库检、周期性检验等（共列 9 种），QMS 要足够灵活，**支持自定义** | L26 |
| 2） | 各客户要求不同、各供应商能力不同，同一物料可以按**供应商/客户/工序/检验类型**维度设不同的验收标准，做到"**一个标准，分类呈现**"（加粗） | L27 |
| 3） | 同族物料的很多检验项相同，应抽出共性建立"**通用标准**"（加粗）；重复的检验项不必重建，直接引用 | L28 |
| 4） | 需要工序控制：通过工艺流程把各工序串起来，适合流水线作业 | L29 |
| 5） | 常规抽样方案有 **AQL、固定数抽样（或固定数梯度抽样）、百分比抽样**（原文写作"百比分抽样"）等，QMS 都应支持 | L30 |
| 6） | 可抽象出独立检验项，如镀层厚度、钢丝直径、电机转速：一共有多少个规格？每个规格质量如何？可在同族物料/供应商/客户/产线/工单之间对比 | L31 |
| 7） | 检验作业不需要专门的 SOP 文档，所有要求都写在检验标准规则里（**检验项、规格标准、样例照片、图纸**…）；**抽样数量、拒收标准、批次合格**都由系统计算并判定；检验员只负责输入数据、提交单据。"消灭操作手册"，即"**傻瓜式QMS系统**"（加粗） | L32 |

**§2.2 检验操作执行**（L35–L41）

| 条 | 要点 | 出处 |
|---|---|---|
| 1） | QMS 要集成的系统很多，如 ERP、WMS、MES、APS、OA、PLM 等，需要有规范的接口 | L35 |
| 2） | 检验任务调度：按**供应商、物料类型、仓库区域、车间、产线、工序**的不同，自动把任务推送给对应的检验员 | L36 |
| 3） | 根据待检物料的质量情况，要有"**跳检、合批、预警、升级**"（加粗）等管控措施 | L37 |
| 4） | IPQC 可设首检/巡检/末检等巡检计划，按时（**如 2h/次**）自动把巡检任务推送给相关负责人 | L38 |
| 5） | 检验过程中可随时查询该物料的**图纸**、历史检验缺陷履历、历史客诉缺陷履历，并在线查看作业指导书等 | L39 |
| 6） | 发生不合格时，可以一边检验一边登记不合格品，便于启动 **MRB 评审** | L40 |
| 7） | 权限管控：金加工、注塑、SMT、装配等各车间的数据，检验员之间互相隔离、不可见；管理层有权查看部分或全部车间的数据 | L41 |

### 2.10 EW §3 不合格品管理（L43–L47）
1. 不合格品来源：IQC、IPQC、FQC、OQC、客诉不合格品、车间快速登记等。【EW §3-1，L43】
2. 不合格品处理方式与流程审批，有些企业要求在 OA 或 BPM 中审批。【EW §3-2，L44】
3. 不合格品处理涉及的质量成本，以及费用承担部门的管理。【EW §3-3，L45】
4. 处理过程中能随时查看原始的检验记录单或客诉记录单。【EW §3-4，L46】
5. 处理完成后可能需要开 (S)CAR，让供应商或内部整改（CAPA）。【EW §3-5，L47】

### 2.11 EW §4(供) 供应商协同（L49–L54）
注意：本节的"客户"指使用 QMS 的企业本身（站在供应商的角度称之为"客户"）。
1. 供应商提交检验数据后，数据自动同步到客户内部系统，客户可随时查阅，或对同一批次订单的数据做对比。【§4(供)-1，L49】
2. 数据积累后可做更直观的对比：供应商与内部的合格率、批次合格率、Pp/Ppk 对比。【§4(供)-2，L50】
3. 供应商出于成本考虑，在保证合格的前提下，关键特性的数据一般会尽量**贴近下公差线**（如镀层厚度、电机转速、钢丝直径），QMS 能直观呈现这些细节。【§4(供)-3，L51】
4. 内部发现 IQC 不良时，可把不良信息实时分享给供应商。【§4(供)-4，L52】
5. 来料不良需要供应商整改时，可直接开 SCAR；供应商按客户要求整改，完成后提交客户审批，客户可实时跟踪整改进度和状态。【§4(供)-5，L53】
6. 如果需要让供应商了解评审详情，可把评审记录报告公开给供应商；评审 Findings 同样可以开 SCAR 要求供应商整改并跟踪。【§4(供)-6，L54】

### 2.12 EW §4(客) 客诉管理（L56–L61）
1. 客诉类型归纳，如制程问题、研发问题，可以有**无限下级分类**，方便以后统计分析。【§4(客)-1，L56】
2. 客诉信息登记（可能会与 CRM 集成），表单字段灵活，能自定义添加字段。【§4(客)-2，L57】
3. 一条客诉可能涉及 N 个物料，一个物料可能涉及 N 个缺陷。【§4(客)-3，L58】
4. 客诉升级机制，如长时间不处理就通知领导。可按**客户名称、物料类型、严重程度、投诉类型**分别设置不同的升级机制。【§4(客)-4，L59】
5. 客诉处理，如换货、维修、赔款等，可能需要审批。【§4(客)-5，L60】
6. 需要整改时开 CAR，启动整改（CAPA）。客诉分**两段式**处理：第一阶段"快反遏制"，从短期维度尽快让客户满意；第二阶段"寻因改进"，从根源彻查原因、永久消除同类问题。【§4(客)-6，L61】

### 2.13 EW §5 纠正预防（CAPA）（L63–L67）
1. CAR 管理：来源有不合格品、客诉、问题 Finding 等；也可给供应商开 SCAR 并监督进度；**CAR 关闭需要审批**。【§5-1，L63】
2. 如果同类问题整改过，可以关联历史 CAR。【§5-2，L64】
3. 事先做好 CAPA 任务模板，可直接调用，一键分发任务。模板规定每个阶段的完成时间；阶段完成后可能需要审批；没按期完成就启动升级机制。【§5-3，L65】
4. CAPA 的每个任务都能上传文字说明、图片、附件等；任务关闭可能需要领导验证。【§5-4，L66】
5. 可直接打印整改报告，如 8D 报告。【§5-5，L67】

### 2.14 EW §6 质量评审（Audit）（L69–L73）
1. 评审类型：支持 5S 审核、体系审核、供应商审核、分层审核等各类审核。【§6-1，L69】
2. 评审清单：建立审核模板；一个评审条目可被不同的审核模板调用，并能统计该条目的审核次数、审核结果等。【§6-2，L70】
3. 评审计划：可自定义单次或周期性审核计划，系统自动推送给相应负责人。【§6-3，L71】
4. 评审执行：审核人员可实时记录评审证据（文字、照片、视频）和评审 Findings；评审时能展示同一审核条目的历史情况；Findings 可直接启动 CAR（与 CAPA 模块集成）。【§6-4，L72】
5. 评审报告：可按模板打印，便于后续跟踪和归档。【§6-5，L73】

### 2.15 EW §7 问题管理（L75–L78）
1. 问题类型归纳，如 5S 问题、生产问题、原材料问题，可以有无限下级分类。【§7-1，L75】
2. 质量问题登记：新建问题记录（自定义表单，可无限增加字段），并配置问题升级机制。【§7-2，L76】
3. 问题处理：分配任务，监督任务执行。【§7-3，L77】
4. 与 CAPA 模块集成：开 CAR，启动纠正预防措施。【§7-4，L78】

### 2.16 EW §8 量具管理（L80–L83）
1. 量具类型，如三坐标、游标卡尺、硬度计等。【§8-1，L80】
2. 量具台账（量具基本信息列表）；每个量具的表单可直接查看履历，如校准、保养、维修记录。【§8-2，L81】
3. 量具的校准、保养、维修计划与执行：可设周期性计划，能事前提醒，可登记相关费用。【§8-3，L82】
4. 量具模块的统计报表。【§8-4，L83】

### 2.17 EW §9 项目管理（L85–L89）
- 导语：比如研发质量项目管理，对项目做阶段式管理，支持阶段评审。【L85】
1. 项目模板：定义阶段内容和下辖的任务列表。【§9-1，L86】
2. 任务可以关联或发起检验、评审、问题登记、整改等。【§9-2，L87】
3. 项目阶段可要求完成时间，有阶段升级机制和阶段审批流程。【§9-3，L88】
4. 项目报告：可把所有任务、检验记录、评审记录、问题记录、整改记录等一键生成报告打印。【§9-4，L89】

### 2.18 EW §10 全景追溯（L91–L94）
- 导语：针对关键产品、客户、供应商，可快速检索到所有质量事件。QMS 把 IQC、IPQC、FQC、OQC、不合格品处理、客诉管理、质量问题发现、纠正预防、评审管理等所有质量活动关联起来，实现**一键质量追溯**，比如查出与某料号、订单、客户相关的检验记录、不合格品、客诉、质量问题、纠正预防及对应任务详情。【L91】
1. 查询条件：**料号/供应商代码/客户代码/单号（采购单/工单/发货单）/批号**；可查出的质量事件：检验记录、不合格品、客诉、整改措施、质量问题、任务等。【§10-1，L92】
2. 各质量事件有没有后续跟踪？关联关系如何？例如：某检验记录是否产生了不合格品？这个不合格是怎么处理的？有没有整改？谁在跟踪？【§10-2，L93】
3. 客户审厂或内部质量会议时，可迅速查出：该物料是否被投诉过？是否整改过？谁在跟踪？状态如何？据此立即反馈客户，并制定下一步计划。【§10-3，L94】

### 3.2 原文可见的闭环链路【推断：按原文语句串联】
1. **检验 → 不合格 → 整改**：检验时自动判定 → 边检边登记不合格品 → MRB/处置审批 → 质量成本与费用承担 → 开 (S)CAR → CAPA 任务（模板、阶段、审批、超期升级）→ 任务关闭（领导验证）→ CAR 关闭（审批）。【汇总 R2–R7、R11、R14；EW §2.2-6、§3、§5】
2. **客诉 → 整改**：多渠道登记 → 按规则升级 → 处理（换货/维修/赔款，审批）→ 快反遏制 → 开 CAR 寻因改进。【汇总 R8；EW §4(客)】
3. **评审 → 整改**：评审计划 → 执行（证据、Findings）→ 自动生成发现项 → 开 CAR；对供应商开 SCAR → 供应商在线整改 → 客户审批。【汇总 R10；EW §6、§4(供)-6】
4. **问题 → 整改**：登记 → 升级 → 分配任务 → 开 CAR。【汇总 R9；EW §7】
5. **目标 → 整改**：质量目标未达标 → 通知 → 触发 CAR/纠正预防。【汇总 R18】
6. **订单 → 检验**：采购订单跟踪 → 报检 / 交货前触发检验。【汇总 R20】
7. **周期性试验**：按数量或时间自动计算 → 提醒 → 试验 → 供应商提交周期性试验报告（英）。【汇总 R6、汇总-英 R19】
8. **追溯**：所有链路通过料号、单号、批号等关联，实现一键追溯。【EW §10】

### 3.3 原文出现的状态 / 结果值
- 判定结果：合格/不合格（Pass/Fail）；批次合格。【汇总 R2–R5；EW §2.1-7】
- 不合格处置结果：特采、报废、挑选【汇总-中 R7】；退货、让步接收、返工、返修、报废【EW §1-1】；英文版称"Customized NCR disposal result"，即处置结果可自定义【汇总-英 R7】。
- 客诉处理结果：换货、维修、赔款等。【EW §4(客)-5】
- 整改状态：是否整改、整改进度、是否关闭。【EW §1-1、§10-2/3】
- 流程节点词：审批、升级、验证、关闭、跟踪。原文没有给出完整状态集合和流转规则，本资料未涉及。

## 6. 与"工业图纸气泡识别"的关联点

### 6.1 明确判断
**结论：没有。** 两份必读来源中，**都找不到**以下任何能力的描述：
- 图纸识别
- 气泡标注/编号
- OCR
- CAD/PDF 图纸解析
- 尺寸、公差、几何公差、粗糙度、技术要求的自动提取
- 检验特性清单的自动生成

检验规则模块的覆盖范围如下：
- **"检验规则"模块（序号 24，英文名 Inspection Plan）的原文全部内容**：
  - 中文：功能描述"产品检验标准的统一管理"；场景"需要对产品进行质量检验管理"；亮点"检验方法，检验内容，缺陷描述等进行标准化，规范化，便于进行数据分析"。【汇总-中 R25】
  - 英文："Standardized inspection requirements"；"Inspection standards for internal and to define standard inspection requirements for customers"；"Standardized inspection method,s details, defect details,enhance the ability of quality  data analysis and requriement management."（原文拼写如此）。【汇总-英 R25】
  - 结论：它覆盖的是**人工维护的检验标准主数据**，内容是检验方法、检验内容、缺陷描述的标准化，以及内部标准和面向客户的标准检验要求。原文**没有提到**图纸、尺寸、公差、特性，也没有提到任何自动生成或导入方式。
- 图纸在两份资料里只以**被动资料**的身份出现：
  - 作为文档类型存储和共享（英文版文档管理，可锁定编辑）【汇总-英 R15】
  - 作为检验标准规则的组成之一（和检验项、规格标准、样例照片并列）【EW §2.1-7】
  - 检验时可随时查询该物料的图纸【EW §2.2-5】
