## 1. 核心摘要

V3方案 p13–23（第 5–8 章）是整套设计里「图纸 → 标准 → 方案 → 检验 → 判定/报告 → 限制/处置」的主链规则，也是图纸气泡识别与 QMS 衔接的核心。

**第 5 章：受控基准。**
- 零件身份、工程修订、图纸文件修订、特性稳定ID、特性修订、标准修订、方案修订，7 类身份/版本分别管理。
- 气泡号只是图面显示标记，不能作为跨版本主键。换图时要记录沿用、新增、删除、拆分、合并或无法确认的映射，无法确认的交给工程人员处理。
- 每条要求保留 8 个字段：图纸修订、页码、气泡号、原文/截图、特性身份、单位、公差/属性、方法。
- 气泡采用或手工录入后，先形成不隶属任何场景的技术标准版本；检验方案再显式选定一个标准版本、场景和项目，按 measurement 或 single_count 安排执行。
- 方案以不可变内容摘要标识；同一方案修订只有一个批准权威；Axis 工作台与 QMS 分工，不重复批准。
- 工程变更要反查 6 类范围并逐范围采用；进行中的任务保持原快照（本轮不提供换版）；已签发报告只能被替代，不能追改。
- 计数抽样规则只能来自授权标准表或企业批准规则。

**第 6 章：检验执行。**
- 建单时不得临时修改规则；任务、轮次、样本分开建模。
- Axis 回传的结果由服务器重新读取；设备导入分 7 步，原子、幂等提交；真实超差必须入账。
- 用 Decimal 做精确判定；规格表达有 7 类。
- measurement 只证明被检范围（evidence_only），只有 single_count 才按 Ac/Re 判批。
- 更正和复检只追加记录，不覆盖原记录。

**第 7 章：结果分层。**
- 测量事实、技术判定、报告签审、接受依据、用途资格、实际执行六类结果相互独立。
- 不默认双人审批，也不加放行申请。
- 报告内容固定，签名绑定内容摘要；CoC 只在合同适用时才必备。
- 质量限制必须明确范围和受限动作。

**第 8 章：处置闭环。**
- 质量事件、NCR、质量限制三者分立、可关联。NCR 分行处置，记录对象、数量和单位；NCR 与 CAPA 各自关闭。
- 实物谱系、额度预占核销等已移到第 17 章作为候选；物流、承运、退运当前不建设。

**图04 变更与逐范围采用**（p14 内嵌；图册04）

- 副标题：跨版映射、影响评估、采用决定和实施验证分开；旧事实及已签发报告不回写。
- 主线 4 步：
  1. 新工程或图纸修订（旧新文件与变更理由；气泡编号不是永久主键）
  2. 确认稳定特性映射（沿用/增删/拆并/未明；无法确认转人工评估）
  3. 生成完整影响清单（方案/任务/在制/库存/已发；风险、责任人与期限）
  4. 批准逐范围决定（沿用旧版/采用新版；追加验证或受控处置）
- 第 4 步之后分为 4 个范围：

| 范围 | 图中规则 |
|---|---|
| 新建任务 | 按有效适用规则建单；绑定获准适用的依据修订 |
| 在制与开放任务 | 原任务快照与实测保留；需新要求时显式新建任务 |
| 库存与待交范围 | 评估筛选/返工/让步；必要时按动作建立 Hold |
| 已出库或客户现场 | 历史交付事实继续保留；客诉和影响处理关联记录 |

- 汇合后判断"逐行采用与控制证据及责任承接齐备？"
  - 否：未齐则保持待办（退回具体影响行补齐；保留责任人及处理期限）。
  - 是：关闭本次变更（旧事实及已签发报告保持原样；新报告使用新版本和相应签审）。
- 脚注："逐范围核验实际采用、处置执行及必要验证；本次变更关闭不解除其他独立 Hold。"

#### 7.1 六类独立结果（p18 表）

**图06 独立状态与按策略门禁**（PDF p18 只有图题；图册06）

- 4 条泳道：

| 泳道 | 节点与流转 |
|---|---|

| 客户状态 | 未确认（没有回复） | p23 ¶3 |

交叉参考（范围外，V3方案 p53 附录A3.2）：轮次另外分 4 个状态维度保存。
- execution_state：planned / active / submitted / closed / voided
- technical_state：measurement 用 conforming / nonconforming / insufficient；single_count 用 accepted / rejected 及未评定等
- report_state：none / draft / frozen / review_required / approved / superseded / voided
- policy_outcome：pending / auto_accepted / manual_review_required / accepted / rejected

这与 7.1"六类独立结果"的思路一致。

### 3.3 生命周期主链

1. **基准链**（p13 ¶1–¶4）：图纸修订 → 气泡定位 → 特性（稳定ID/修订）→ 采用形成技术标准版本（或手工标准）→ 方案显式选定标准版本、场景、项目、策略 → 发布（不可变内容摘要，单一批准权威）→ SIP 由方案和标准版本生成或引用。
2. **变更链**（p13 ¶5、p14、图04）：变更申请 → 稳定特性映射 → 影响清单（6 类范围）→ 逐范围决定 → 按 4 类范围落实 → 逐行证据齐备 → 关闭变更（不解除其他 Hold）。
3. **检验链**（p15–17、图05）：按产品和场景选方案开检 → 固定三层采用（场景/标准/方案版本）→ 轮次采集/导入 → 格式与对象校验 → 原子保存事实 → 完整性与可采纳性判断 → 分层技术判定 → 真实报告（缺项不补值）→ 不良转事件或 NCR。
4. **结果链**（p18–19、图06）：任务进度、事实与技术、报告策略、受控实物动作四条线相互独立，可以同时处于不同状态。
5. **限制与处置链**（p19–23、图07、图08）：质量事实 → 明确范围 → 判断是否有适用限制 → 分行处置 → 核对覆盖范围 → 按策略解除 → NCR 本次关闭；CAPA 按风险另行启动，各自关闭。

## 6. 与"工业图纸气泡识别"的关联点

本段是 V3 中最直接定义「气泡 → 特性 → 标准 → 方案 → 检验」衔接规则的部分。下表「V3 原文规则」一列附出处；「对气泡识别服务的含义」一列均为【推断】。

| # | 关联点 | V3 原文规则 | 对气泡识别服务的含义【推断】 |
|---|---|---|---|
| 1 | 气泡的业务定位 | 气泡图把尺寸、GD&T、技术注释或其他检验要求"定位到可执行的特性记录"（p13 ¶2） | 识别服务的产出不应只是图上的序号，而是「图面位置 + 结构化要求」成对的数据（交叉参考 V3方案 p4 借鉴 [S11]："图面定位与结构化要求成对维护"） |
| 2 | 气泡号不是主键 | 气泡编号只是显示标记；移动或重新编号不改变特性身份（p13 ¶1–¶2） | 识别服务要给每个特性分配与气泡号无关的稳定 ID；重新排号、调整气泡位置只改变显示属性 |
| 3 | 识别输出的字段 | 每条要求 8 个字段：图纸修订、页码、气泡显示号、原文或截图片段、特性身份、单位、公差/属性表达、检验方法（p13 ¶2） | 可作为识别结果 schema 的最低集合。"原文或截图片段"可以由 OCR 文本和框选区域截图提供 |
| 4 | 识别结果不等于标准 | "图纸气泡采用……先形成产品适用的技术标准版本"（p13 ¶3）；[S11] 说明"自动识别结果仍需核对"（交叉参考 V3方案 p45、p4："自动识别不等于已批准标准"） | 识别结果先作为候选，经人工核对、"采用"后才形成标准版本；QMS 应记录哪些字段被人工修改过 |
| 5 | 7 类规格表达 | 双边、单边、范围、属性、通止规、证书核验、特殊表达；"形位与复合要求不能强行解析成一个上下限"（p17 ¶1） | 识别器需要输出公差类型分类；GD&T 框格（基准、修饰符、复合公差）应保留结构化原样，不能压缩成上下限 |
