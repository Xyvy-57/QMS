## 建议演示顺序

1. 在「技术标准」查看已发布标准；「新建修订」会生成独立草稿。
2. 在「工序与方案」选择方案，点击节点设置前置依赖、检验特性和每项样本数。可复制单工序或整套方案。
3. 保存并发布方案，再创建批次任务。检验场景、标准与方案在创建时冻结。
4. 录入实测值。空值保持待检，格式错误阻止完成，超差如实保留。计量模式只证明被检范围，不自动判整批合格。
5. 上传现场图片，完成检验员手签；仅任务显式选择要求时才必须审核员签名。
6. 完成本轮生成独立报告，导出CSV或打印。
7. 对超差登记NCR，添加处置行、执行凭据和关闭核验。新建复检轮次时结果为空，原检值和原报告保留。

初始5个任务、3个技术标准与5套场景方案都是明确标记的本地演示数据。浏览器验证另外生成的 `DEMO-UI-验证批次` 是验收用记录，仅存在本机预览地址的浏览器存储，不写入种子代码。

## 复用边界与实际限制

- 标准工序与方案复用的是结构和安排。标准特性仍显式来自一个确定标准版本，跨产品不能自动沿用公差。
- 工序关系是可编辑的DAG编排，支持分支/汇合并校验环和引用。当前统一录入方案关联特性，未实现生产节点派工、逐节点执行门禁或MES联动。
- 图纸标注是独立软件 iframe，网页没有重写OCR。默认地址取自用户截图，可在连接设置修改。外部服务登录、证书及 frame-ancestors/X-Frame-Options 需服务端配合；当前未验证该服务实际可嵌入，也未实现生产后端结果同步。
- JSON 是本地人工导入适配入口，不冒充服务端回传。生产需要 QMS 后端鉴权并读取已保存对象/版本，不能信任浏览器回传的最终判定。
- 拍照入口使用 `accept="image/*" capture="environment"`；是否直接启用相机由设备与浏览器决定。桌面提供文件选择。
- 签名是本地手写记录，未接企业身份源、可信时间戳、认证电子签章或防篡改服务。
- 数据保存在localStorage。照片和签名占用浏览器存储；容量不足会提示，设置中可导出全量JSON备份。当前未提供备份恢复界面。
- NCR限制只作本地记录，不拦截真实物流/ERP。质量限制与NCR独立关闭。
- 未提供AQL标准表、自动判批、真实CMM/蓝牙采数、SPC统计、Excel报告模板解析和供应商门户。

## 实现与维护

所有样式、脚本均已内置最终 HTML，字体使用系统字体，核心演示无 CDN 依赖。源代码在 `src/`，通过 `node build.mjs` 重新生成单文件；不要只编辑构建产物。

- `core.js`：版本快照、任务/轮次、精确十进制判定、NCR、报告、存储。
- `process.js` / `process.css`：工序库、可视化方案编排。
- `inspection.js` / `inspection.css`：五类检验、证据、签名、报告。
- `app.js` / `styles.css` / `shell.html`：工作台、图纸iframe、标准、NCR和公共界面。

运行检查：

```sh
node --test tests/core.test.js tests/process.test.cjs tests/inspection.test.cjs
node build.mjs
```
