# 兼容重建差异与实施顺序

本文件整理截至 2026 年 11 月 17 日（Asia/Shanghai）的本地证据。目标是在现有 QMS Demo 的技术标准、检验方案、批次任务、实测轮次、NCR 和报告快照之外，补齐与线上气泡图软件兼容的对象和交互。本文仅提出重建与适配方案，没有修改 Demo，也没有执行线上新增、覆盖、删除或发布操作。

## 2. 保留 QMS 层，新增气泡图适配层

现有 [process.js](/Users/weiyi/Desktop/苏州worlder开发相关/私有QMS交付/01_可运行Demo/src/process.js) 已实现工序复用、检验特性选择、抽样数、方案修订和批次创建。它解决的是 QMS 检验策划与执行问题。线上气泡图中的“工序模板”则是全局共享的工序图定义，二者需要映射，不能直接共用同一张表、同一个状态字段或同一种版本规则。

建议分层如下。下列对象名是重建建议，除反引号中的已观察字段外，不宣称为线上原字段。

| 对象层 | 应保存的内容 | 适配原则 |
| --- | --- | --- |
| 气泡图原始对象 | 空间、图纸包、源文件与页面、图纸资料、保存的标注版本、气泡原文与几何位置 | 保留来源身份和版本；允许重新查看原图与采用时的结果 |
| 全局工序模板 | `name`、`description`、`graph`、`row_version`、创建与更新时间 | 同 ID 更新与乐观锁；平台级权限控制 |
| 空间图纸工序 | 图纸包关联、工序图、关联标注、来源模板 ID 与采用时版本 | 每空间每图纸独立，已有安排不因再次选用模板而直接覆盖 |
| QMS 技术标准 | 核对后的技术要求、限值、单位、检验方法、来源标注版本 | 继续保留发布与修订；识别结果不能自动视为已审核标准 |
| QMS 检验方案 | 检验场景、适用标准版本、范围、抽样、责任与审核要求 | 可引用工序图及图纸工序来源；与全局工序模板的字段分开 |
| QMS 批次与报告 | 固定标准／方案快照、实测、照片、签名、复检轮次、NCR、报告 | 历史任务继续使用采用时快照；新版标注、模板或标准不回写历史 |

适配层至少需要表达 `workspace_id`、`drawing_package_id`、采用的冻结标注结果标识、`source_template_id`、`source_template_row_version`，以及本地技术标准与检验方案的对应关系。冻结标注结果的真实 ID 字段尚未拿到完整空间 API body，应作为待核实契约，不能自行命名后声称已兼容。

## 4. 用户角色、系统范围与工作空间权限

前端角色判定可以定位到 `/tmp/qms_assets/index.js` 的 `ku=e=>e==='super_admin'`，被模板页面导入为权限判断函数。全局工序模板新建／编辑／删除仅对 `super_admin` 显示并启用；普通用户能查看、选用、关联图纸、下载工序 Excel。模板编辑器对普通用户禁用输入和画布修改，新建路由另显示“仅系统管理员可以创建工序模板”。

平台角色和工作空间成员角色必须分开。

- 页面登录人显示“普通用户”。
- [10_workspace_search.json](/Users/weiyi/Desktop/苏州worlder开发相关/私有QMS交付/02_线上交互与接口勘察/responses/10_workspace_search.json) 的个人空间成员字段为 `member_role:"admin"`。
- 因此空间管理员不等于平台 `super_admin`；不能因为 `member_role` 是 `admin` 就开放全局模板写入。
- 系统提供的公差、检具与报告模板可能在工作空间页面内被选择或复制；对象为系统来源不等于其读取 endpoint 可省略 workspace 上下文。现有 `WORKSPACE_REQUIRED` 响应已说明这种区别。
- 当前证据尚不能完整确定空间内每一种读写权限、团队成员角色继承、用户自定义与空间自定义的后台归属规则。实现前需补充相应契约与授权测试，不能用一个全局 `canEdit` 布尔值概括。

页面权限只是第一层。兼容服务仍需按系统角色、空间成员关系和资源归属分别校验，前端隐藏按钮不构成安全边界；本次未用写入请求验证服务端权限。

## 5. 工序图模型、版本与保存差异

生产模板的真实 GET 响应 [02_process_template_detail.json](/Users/weiyi/Desktop/苏州worlder开发相关/私有QMS交付/02_线上交互与接口勘察/responses/02_process_template_detail.json) 包含 `id/name/description/graph/row_version/created_by/creator_name/created_at/updated_at`。样例 `row_version` 为 10，有 5 个节点、5 条连接，结构为起始节点分为两支、汇合后再继续。

```json
{
  "version": 1,
  "nodes": [{
    "id": "stable-node-id",
    "code": "2.1",
    "name": "工序名称",
    "description": "工序说明",
    "position": { "x": 80, "y": 236 }
  }],
  "edges": [{ "id": "stable-edge-id", "source": "node-a", "target": "node-b" }],
  "viewport": { "x": 0, "y": 0, "zoom": 1 }
}
```

上例是字段结构示意，不是一份可直接通过端点校验的完整工序图。

### 5.1 几何位置与执行顺序分离

生产代码明确：“箭头表示先后关系。分支与汇合表示并行安排；工序位置不影响执行顺序。”节点拖动只修改 `position`；平移／缩放修改 `viewport`。增加、删除或连接节点时，根据拓扑层级重新生成 `code`：单节点层用 `1、2、3`，并行层用 `2.1、2.2`。同层编号顺序来自节点数组，不由坐标排序；仅默认名称随编号变化，自定义名称保留。

本地 Demo 每次渲染重新计算坐标，节点显示 `01、02…`，边没有独立 ID，未保存 viewport。兼容实现应新增可持久化布局与稳定 ID，并让“自动布局”成为明确操作；不得因拖动节点而改执行依赖，也不得把画布编号作为特性稳定身份。图上的先后关系仍不等于已经实现 MES 执行门禁，本地统一实测页面应继续如实说明能力边界。

### 5.2 row_version 与业务修订分离

生产模板更新采用同 ID 的 PUT，并提交 `row_version`。本地 QMS 发布方案后修改生成新 ID／新业务修订，旧任务继续使用快照。两种机制都应保留，但分别适用于不同对象：

- `graph.version`：图结构 schema 版本。
- `row_version`：当前对象的并发控制版本。
- `source_template_row_version`：图纸工序采用模板时的来源版本。
- 图纸版次、标注冻结版本、QMS 标准／方案修订：各自独立的业务版本。

生产“关联图纸”先完成模板保存，冻结模板 payload、ID 和 row version，再读取目标图纸工序。若目标已有安排则进入现有安排；若不存在才创建，并携带 `source_template_id` 与 `source_template_row_version`。后续不能用来源模板的最新版本覆盖采用时版本。后端冲突如何响应、是否支持历史模板读取与重放，当前证据不足。

### 5.3 保存体验与结构约束

前端代码有手动保存、自动保存、保存失败保留内容、重试、离开确认和 `beforeunload`。自动保存约 1 秒静默触发，连续修改约 5 秒达到触发上限；保存请求串行，自动保存期间继续编辑的内容不能被旧响应覆盖。路由变化和组件卸载会阻止迟到响应更新错误对象。这些需要在接入远程 API 后补齐；本地存储成功不能代替远程保存确认。

| 校验对象 | 生产前端已观察规则 |
| --- | --- |
| 模板名称／备注 | 名称必填且 ≤255 字符；备注 ≤2000 |
| 节点／边数量 | ≤200 个节点；≤1000 条连线 |
| 节点 ID／边 ID | 必填，≤80 字符；各自集合内做大小写折叠后的唯一性校验 |
| 节点 code | 必填，≤32 字符，大小写不敏感唯一 |
| 节点名称／说明 | 名称必填且 ≤80；说明 ≤2000 |
| 位置／viewport | 有限坐标，范围 ±100000；zoom 为 0.1–3 |
| 连接 | 端点存在、无自连、无重复 source-target、无环 |
| 空图／不连通图 | 通用 graph validator 没有禁止；关联、下载或业务创建可能有额外限制 |

不能把 Demo 的“发布检验方案必须连通、有标准且至少关联一个检验特性”直接套到全局工序模板保存。前者是 QMS 业务约束，后者是工序图定义约束。

## 6. 已知接口边界与待补契约

以下路径由本地 JS 封装观察，实际服务地址通常还带 `/api/v1` 前缀。只有对应 `responses` 中有内容的 GET 已取得业务 JSON，其余只是客户端契约线索。

| 范围 | 已观察调用 | 版本／空间语义 |
| --- | --- | --- |
| 全局模板读取 | `GET /process-templates`、`GET /process-templates/{id}` | `skipWorkspaceHeader:true`；列表支持 page/page_size/keyword |
| 全局模板修改 | `POST /admin/process-templates`、`PUT/DELETE /admin/process-templates/{id}` | PUT body 与 DELETE query 使用 `row_version`；未做写入验证 |
| 空间图纸工序 | `GET/POST/PUT/DELETE /drawing-packages/{packageId}/process-arrangement` | 显式 `X-Workspace-ID`；PUT 带 row_version；DELETE 带 arrangement_id 与 row_version |
| 模板关联图纸 | `GET /process-templates/{templateId}/drawings` | 显式 workspace，独立分页 |
| 图纸选择／台账 | `/drawing-packages`、`/drawing-packages/process-picker-counts`、`/drawing-process-arrangements` | 图纸请求可带 include_process_summary；空间业务完整 body 未取得 |
| 图纸工序下游 | `.../process-arrangement/annotations`、`.../process-arrangement/inspection-reports` | 客户端有读取／创建入口；标注关系与创建 body 仍待核实 |

下一轮契约补充应集中于：带有效空间上下文的图纸包、冻结标注、图纸工序与关联图纸响应；公差来源与规则 body；检具推荐；报告字段字典、Excel 模板结构；质检单及质检单模板 body；版本冲突、权限拒绝、缺失资源和失效冻结结果。HTTP 状态与 headers 需要通过明确的网络证据补录，不能从页面错误文案反推。

## 7. 实施顺序与可验收结果

| 顺序 | 工作 | 完成标准 |
| --- | --- | --- |
| 1 | 定义来源身份、权限与 workspace 适配契约 | 平台 role 与 member_role 分开；全局读不误带空间、空间读不漏空间；切换空间取消旧请求并清理选择状态 |
| 2 | 图纸包台账、详情、冻结标注只读接入 | 能按页查看原图与气泡，保留原文、空值、结果来源、待确认状态；选择确定的冻结版本；不读进行中标注替代冻结结果 |
| 3 | 全局工序模板台账与只读画布 | 普通用户只能查看／选用；现有真实 JSON 能无损往返 graph 字段；移动／缩放不改依赖；正确显示分支汇合和关联图纸范围 |
| 4 | 空间图纸工序创建与编辑适配 | 选用模板保留 source_template_row_version；已有安排不被隐式覆盖；row_version 冲突保留本地编辑并提供重载／比较入口 |
| 5 | 标注到受控标准、方案的映射 | 人工核对后生成 QMS 标准修订；技术项稳定 ID 与来源标注 ID／版本有对应；公差应用可追溯；原任务快照不变 |
| 6 | 两种质检创建与模板复用 | 从冻结图纸或检验模板建立检验范围；批次、工单、供应商与样本信息完整；复用不携带旧实测结果；保持现有 QMS 轮次/NCR闭环 |
| 7 | 报告版式适配 | 系统模板可预览／复制到空间，空间模板独立编辑；字段映射、试填、分页与原始 Excel 版式经真实文件验证；固定 HTML/CSV仍独立保留 |
| 8 | 管理员全局编辑与完整回归 | 在适用授权及测试空间完成管理员写入、并发、权限、失败重试和导出测试；记录真实响应后才宣称兼容通过 |

实施不需要等待所有未知项清零：可先用真实已获取的全局模板 JSON 和页面字段建立只读契约测试；依赖空间业务 body 的映射保持显式“待接入”。不得用随机模拟结果冒充真实服务响应，也不得用按钮上的成功 toast 作为远程提交证据。

推荐的关键回归场景包括：普通用户打开 `/process-templates/new`；空间管理员尝试修改全局模板；A/B 空间快速切换；模板保存后继续输入并收到旧响应；同图纸重复选用模板；拖动节点但不改拓扑；模板修订后旧图纸工序来源版本不变；当前标注未保存但存在冻结版本；缺失公差不补零；模板复用不带实测；报告快照与原检／复检轮次一致。

## 8. OCR 与识别效果的证据限制

当前已有样例包含“文化工厂”“1# 楼北立面图 1:100”“1# 楼东立面图 1:100”，属于建筑立面类内容。结果页有 69 个气泡且大量状态为“待确认”，还出现尺寸、粗糙度、其他类别与检具推荐的待核对结果。

这些记录可以验证：图纸包列表、保存结果展示、气泡详情、历史、导出选择和下游创建入口的产品流程。它们不能证明机械零件 OCR 准确率、GD&T 提取、公差理解或检具匹配可靠性；69 个气泡也不是 69 个已验证正确的机械特性。

机械场景识别验收需要另行准备有人工基准的机械图纸集合，覆盖尺寸、双向／单向公差、孔轴配合、形位公差、粗糙度、螺纹、焊接、技术要求、单位与多页情况。分别统计检测、识别、结构化与规则应用错误，并保留人工核对结果。当前材料没有这套基准，不应输出准确率数字。
