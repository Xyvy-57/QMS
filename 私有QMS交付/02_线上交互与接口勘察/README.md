## 证据等级

| 等级 | 含义 | 可作什么依据 |
| --- | --- | --- |
| A：实际响应 | 已登录浏览器导航到已知GET端点，页面直接显示JSON，原样语义保存 | 该具体GET请求的返回字段、值、应用层code |
| B：页面可见 | 正常业务页显示的数据/表单/状态，或页面资源清单显示的API URL | 页面交互、可见业务字段、已触发的地址 |
| C：源码推断 | 生产构建文件中的调用与条件 | 请求方法/载荷、自动保存与校验设计；不等于后端实测 |
| 未验证 | 需要写入权限、特定业务样本、额外网络观测能力或后端代码 | 不能填成“通过” |

本次没有HTTP Network面板导出能力：**未捕获HTTP状态码、请求/响应头或HAR**。响应中的 `code:0` 是业务成功码，不是HTTP 200。未读取或保存Cookie、密码、令牌。

## 空间接口采集边界

当前浏览器工具支持导航与页面DOM读取，不支持从请求日志导出body或给GET导航添加 `X-Workspace-ID`。因此：

1. 全局工序模板、空间列表、量具类型字典可通过同会话GET读取，已保存实际JSON。
2. 公差目录/详情、报告模板/字段、图纸库状态直接导航时缺少空间头，实际返回 `WORKSPACE_REQUIRED`。这些错误样本被保留为错误契约，不冒充成功业务数据。
3. 正常SPA页面通过客户端加入空间上下文，实际可见218项公差、10项检具、8个报告模板、2份图纸包。该页面数据与错误导航结果并不矛盾。
4. 空间列表真实响应显示存在1个active个人空间，且当前成员角色为admin；这是空间角色，不等于全局super_admin权限。
5. 想补齐空间接口的原始成功body，需要在已登录浏览器DevTools Network中导出相应响应或脱敏HAR（保留方法/URL/状态/body、移除Cookie与Authorization），或获得网站后端/正式API访问方式。不能把页面DOM数据补写成服务器返回结构。

访问另一个已加载脚本URL尝试读取源码时，被浏览器客户端拦截（ERR_BLOCKED_BY_CLIENT），未换工具绕过，也未影响已取得的响应与页面证据。
