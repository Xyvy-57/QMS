# 工序接口契约与证据分级

采集日期：2026-11-17，Asia/Shanghai。目标是把气泡系统的工序结构和 QMS 业务模型分开，并为后续适配保留可核验依据。

本文只依据本目录已采集页面、JSON 与四份已下载前端源码。编写过程中没有联网、访问浏览器或读取凭据。

## 证据等级与边界

| 标记 | 含义 | 可以支持的结论 |
|---|---|---|
| A | 实际采集 JSON | 本次请求地址、业务 `code`、实际字段、样本值、分页结果 |
| B | 页面可见 | 当前账号可见文案、按钮、数量、空态；不等于 API 授权验证 |
| C | 源码推断 | 前端构造的端点、载荷、校验与交互逻辑；不等于服务端已执行 |

[response_manifest.json](response_manifest.json) 明确说明：通过已登录浏览器导航到 GET 地址，从渲染的文档正文读取 JSON；**没有捕获网络面板的状态码或请求/响应头**。因此 `code: 0` 只能称业务响应成功，不能写成“实测 HTTP 200”。未进行版本冲突写入测试，也不能写成“实测 HTTP 409”。

本次没有执行模板创建、编辑、删除、图纸关联或自动保存写入。源码中出现接口，不代表当前普通用户具有调用权限。

### 模板与 Graph schema

01与04合计19条模板，每条实际字段均为：

```ts
{
  id: string;
  name: string;
  description: string;
  graph: {
    version: 1;
    nodes: Array<{
      id: string;
      code: string;
      name: string;
      description: string;
      position: { x: number; y: number };
    }>;
    edges: Array<{ id: string; source: string; target: string }>;
    viewport: { x: number; y: number; zoom: number };
  };
  row_version: number;
  created_by: string;
  creator_name: string;
  created_at: string;
  updated_at: string;
}
```

列表 `data` 为 `{items,total,page,page_size}`，详情 `data` 为模板对象。02的例子：名称“工序模版 2026-10-31 16:49:38”，首节点名称“清洗”；工序编号为 `1 → {2.1,2.2} → 3 → 4`，包含分支汇合。`viewport.zoom=0.9895549325678996`，坐标也存在小数，不能将其截断为整数。时间字符串含微秒精度和 `Z`。

**已见节点没有 `role`、`sampleCount`、`itemIds`、`scenario`、检验员、实测值或判定字段。** 也未见模板的 `published/draft` 状态。不要把本地 QMS Demo 的字段直接作为线上模板字段。

### 字典与空间

08 的字典结构为 `{revision:number,items:[{code,name,enabled,sort_order,builtin}]}`，本次6项 code：`linear_dimension`、`angular_dimension`、`geometric_tolerance`、`thread`、`surface_roughness`、`welding`。所有项 `enabled=true,builtin=true`，排序0–5。这是检具适用类型，不是工序类型或检验场景枚举。

10 的空间对象实际字段为 `{id,name,type,owner_user_id,status,created_at,member_role,member_count,admin_names}`。样本为 `type:"personal"`、`status:"active"`、`member_role:"admin"`、`member_count:0`、`admin_names:[]`。因为仅见空数组，TypeScript 将 `admin_names` 写为 `unknown[]`，不猜非空元素类型。

## C：Graph 校验与自动编号

`drawingProcesses.js` 第1行字符1710起的 `p`（导出别名A）是前端完整图校验；不等于后端已验证相同规则。

| 对象 | 前端校验 |
|---|---|
| 图 | `version===1`；nodes/edges数组；节点≤200，连线≤1000 |
| 节点ID | string，trim后非空且≤80；Unicode大小写折叠后不可重复 |
| code | string，trim后非空且≤32；大小写折叠后不可重复 |
| name | string，trim后非空且≤80 |
| description | string，trim后≤2000，允许空字符串 |
| position | x/y必须有限number，绝对值≤100000 |
| 边ID | trim后非空且≤80；大小写折叠后不可重复 |
| 边引用 | source/target为string，trim后引用存在节点；禁止自连和同向重复边 |
| 图拓扑 | 禁止有向循环；该函数未要求单一入口、全部节点连通或非空图 |
| viewport | x/y有限且±100000；zoom有限且0.1–3 |

关键原字符串：`最多支持 200 道工序`、`最多支持 1000 条连线`、`工序连线不能形成循环`、`画布缩放范围为 10% 至 300%`。description相关判断在字符2243，viewport在字符2945。

字符4853的 `S(graph)` 使用拓扑遍历，层级为最长前置路径深度。字符5533的 `C(graph)` 将每层单节点编号为 `层级+1`，多节点编号为 `层级+1.同层顺序`；同层顺序继承nodes数组。仅默认名称“新工序”或“工序${旧code}”自动改名，自定义名称保留。**code不是稳定ID。**

字符6337的 `E(graph)` 保留空图或已检测为纵向的图，其余重新纵向布局。编辑器使用 `defaultDirection:"vertical"`。布局位置与执行先后分开，边才表达前后关系。

## C：row_version、保存与离开保护

来源：[ProcessTemplateEditor-DN5NvRSm.js](sources/ProcessTemplateEditor-DN5NvRSm.js)，第1行。

1. 加载取响应的 `row_version`（字符3027），每次成功保存再取响应的新版本（字符4535），不在客户端自行加1。
2. 无修改时仅返回当前 `{id,row_version}`，不发送写入。已有ID调用PUT；新模板调用POST（字符4254）。
3. `q.current` 复用进行中的保存promise（字符3973）；手动保存如果发现期间又有变更，会继续保存最新payload。
4. 保存回应时比较当前payload指纹与发出时指纹（字符4412）；相同时才用响应覆盖UI，否则保留保存期间的新编辑，同时更新版本和baseline。
5. 自动保存等待表达式（字符5326）：`Math.min(1e3,Math.max(0,5e3-(Date.now()-J.current)))`。据此推断为1秒防抖、首次dirty起约5秒最大等待；这是源码计时策略，没有实测网络完成时延。
6. 只有编辑权限、加载成功、dirty时才自动保存；全新且未加节点、未改默认名、未填备注不自动创建。保存、导出或错误状态时跳过：`if(k||N||A)return`。
7. 失败保留修改，文案“保存失败，修改已保留，请重试。”；停止自动重试，可手动重试或新编辑清除错误后再触发。
8. dirty/saving时有 `beforeunload` 和站内离开guard；普通返回按钮尝试先保存再导航。

这里只能说明前端将row_version作为并发控制参数。服务端递增规则、冲突错误码、冲突返回体及合并策略尚未实测。工序Excel调用也会先保存并传 `(id,row_version)`，但下载实现位于未复制的其他模块，下载端点未知。

## C：模板应用到图纸

编辑器“关联图纸”的已见调用路径（字符6405起）按以下顺序：

1. 模板有修改或未保存时先保存，获得ID与row_version。
2. 冻结 `structuredClone` 的模板payload及当前选择的workspace。
3. GET图纸当前 `process-arrangement`。
4. 如果已有安排，此入口直接打开既有安排页，**不执行覆盖POST**。
5. 若无安排，把全部模板节点ID交给外部helper `ve(template,nodeIds)`，再纵向布局、调用安排校验。
6. POST以下已知载荷后打开 `/drawing-processes/{drawingPackageId}`：

```ts
{
  description: template.description,
  graph: convertedGraph,
  source_template_id: template.id,
  source_template_row_version: template.row_version
}
```

证据原字符串：

```js
let n=await pe(t.workspaceId,e.id); ... if(!n){
  let n=de(ve(t.template,t.template.graph.nodes.map(e=>e.id))),
      r={description:t.template.description,graph:n};
  await me(t.workspaceId,e.id,r,{
    source_template_id:t.template.id,
    source_template_row_version:t.template.row_version
  })
}
```

外部helper `ve` 的实现不在这四份留证源码中；不能确认节点UUID是否重建、部分选用是否重连边、服务端是否永久冻结来源版本。列表“选用模板”仅调用 `onUse(id)` 或导航 `/drawing-processes` 携带 `{template:id}`（列表源码字符14686）；不能把编辑器“关联图纸”的规则泛化成所有入口规则。

## 与 QMS 检验标准、方案、实测记录的分离

| 层 | 本次证据 | 接入建议（设计建议，不是线上API事实） |
|---|---|---|
| 全局工序模板 | A：graph/row_version；B：全局只读；C：管理员写入端点 | 原样存储外部graph与版本，node.id为稳定映射键 |
| 图纸工序安排 | B：一份图纸一套工序；C：workspace header及source_template字段 | 按workspace＋drawing package建关联，不跨空间混用 |
| 气泡/公差特性 | 此契约不包含完整冻结标注JSON | 另建图纸版本、标注冻结版本、气泡标识和计量限值映射 |
| 质检单模板/检验方案 | B：复用范围和方案，不含实测结果 | 在QMS层绑定工序node与检验项目、方法、抽样、角色、场景 |
| 实际检验与复检 | 未在工序模板JSON中出现 | 每批独立记录，保存标准/方案快照，实测结果与模板隔离 |
| 报告版式模板 | 与质检单模板为不同页面 | 不混同为工序graph或实测数据容器 |

本地 Demo 已有的 `sampleCount`、`role`、`itemIds`、`IQC/FIRST/IPQC/FQC/OQC`、签名和复检，应归QMS自己的模型或显式适配扩展。未知映射字段保持未知，不能伪装为线上已支持字段。
