# 自研气泡识别软件 · 首期设计说明（草案）

> 版本 v0.1 ｜ 日期 2026-11-17 ｜ 状态：待确认后开工
> 读者：项目负责人、研发、测试

## 1 目标与范围

**目标**：自己做一套可以私有化部署的气泡识别软件（下称“气泡软件”），和 QMS 原型打通“图纸 → 气泡 → 标准 → 方案 → 检验 → 报告 → 不合格处置”整条链，并用自动化测试证明能跑通。

**和之前决定的关系**：QMS 仍然用 iframe 内嵌一个独立的气泡软件，这个决定不变，只是被内嵌的换成我们自己的。QMS“集成设置”里可以随时切回外部的 Worlder 气泡图地址。

**首期功能**（对照 Worlder 气泡图现有菜单）

| Worlder 菜单 | 自研气泡软件 | 说明 |
|---|---|---|
| 图纸标注 | 做：标注工作台 | 上传 → 自动识别 → 校核 → 冻结并同步给 QMS |
| 公差标准 | 做 | GB/T 1804 一般公差表；ISO 286 配合公差计算；图纸级“未注公差等级”设置 |
| 图纸库、图纸管理 | 做：合并为“图纸库” | 图号、版本、零件、材料、状态、历史版本 |
| 图纸对比 | 做 | 新旧版本的特性映射（沿用 / 变更 / 新增 / 删除 / 无法确认），加图面叠加对比 |
| 相似图纸 | 做 | 按特性组成和图面相似度查找，便于复用方案 |
| 工序管理、工序模板、质检单、质检单模板、检具与方法、报告模板 | 不在气泡软件里重复做 | QMS 已经有工序路线与模板、检验任务与报告、检具与检验方法、报告模板。内嵌时顶部入口直接跳到 QMS 对应页面，避免同一份数据维护两套 |

## 2 怎么识别

**输入格式**

| 格式 | 做法 | 准确度 |
|---|---|---|
| CAD 导出的 PDF（文字没有转成线条） | 直接读出文字和位置 | 高 |
| 扫描件 PDF、PNG、JPG | 本机 OCR（离线，不调用任何云服务），横向、竖向文字各识别一遍 | 中，靠校核兜底 |
| DXF | 二期 | — |

**处理步骤**：取文字 → 把相邻的字拼成一条标注（含叠放的上下偏差）→ 解析规格 → 补公差 → 过滤标题栏、图框分区编号、视图名 → 自动摆放气泡并按阅读顺序编号 → 人工校核。

**能解析的写法**

| 类型 | 例子 |
|---|---|
| 直径、半径 | Ø20、Φ20、φ20、R5、SR10、SØ10 |
| 对称 / 不对称偏差 | 20±0.1、20 +0.10/-0.05、叠放的上下偏差、20 0/-0.1 |
| 极限尺寸 | 20.05/19.95、19.95~20.05 |
| 配合代号 | Ø20H7、Ø20g6、Ø20h7(0/-0.021)，按 ISO 286 查出上下限 |
| 角度 | 45°、30°±1°、60°±30′ |
| 倒角 | C0.5、0.5×45° |
| 螺纹 | M8、M8×1.25-6g、2-M6-6H（按通止规计数判定） |
| 数量 | 4×Ø6、4-Ø9 |
| 粗糙度 | Ra1.6、Rz6.3 |
| 形位公差 | 14 种符号或中文名称（平面度、垂直度、位置度、同轴度、圆跳动等），带基准 A/B/C |
| 硬度等理化要求 | HRC 58~62、HB 241~285 |
| 技术要求条目 | “1. 调质处理 HB 241~285” → 理化特性；“去毛刺、锐边倒钝” → 外观特性 |

**公差来源**：每个特性都记录公差是从哪来的：图面标注、未注公差（按标题栏写的 GB/T 1804-m 等级查表）、配合代号查表。后两种标“需核对”。

**框选识别**：在图上拉一个框，只识别框里的文字并生成一个气泡；识别不出来就手工填。自动识别漏掉的、识别错的，都靠这个补。

**每个特性保存**：原文、原图截取、页码、标注位置、气泡位置、置信度、公差来源、校核状态。置信度低的标黄，冻结前必须逐个确认或说明。

**识别结果不等于标准**：只有冻结后才同步给 QMS；QMS 收到后还要生成标准草稿、核对、审核批准。

## 3 稳定特性 ID 与换版

- 每个特性有一个稳定 ID，气泡号只是显示号；拖动气泡、重新编号都不改 ID。
- 上传新版本图纸后，自动和上一个冻结版本做特性映射：综合比较位置、类型、名义值和公差打分，结果分为沿用、变更、新增、删除、无法确认。
- “无法确认”的必须人工选定后才能冻结。沿用和变更的特性保持原 ID，QMS 据此对比差异，并继承检具、方法和特殊特性等级。

## 4 与 QMS 的对接

**启动**：一条命令同时启动 QMS 和气泡软件。两个地址端口不同、来源不同，和正式环境一样要过白名单。

**消息**：沿用 PRD §7.1 已定义的消息，双方都校验来源：

| 方向 | 消息 | 用途 |
|---|---|---|
| 气泡软件 → QMS | `worlder.ready` | 页面就绪，完成握手 |
| 气泡软件 → QMS | `worlder.balloon.frozen` | 冻结通知（批次号、图号、版本、内容摘要、气泡数） |
| 气泡软件 → QMS | `worlder.navigate` | 页面切换，QMS 同步高亮入口 |
| QMS → 气泡软件 | `qms.context` | 当前用户和身份 |
| QMS → 气泡软件 | `qms.navigate` | QMS 顶部入口切换页面 |

**数据**：冻结时由气泡软件服务端生成同步批次号和内容摘要（SHA-256），按 PRD §7.2 提供 `GET /api/v1/open/balloon-sync/{syncBatchId}`。QMS 收到通知后按批次号拉取，核对摘要一致才进收件箱。原型里由 QMS 页面代为拉取，正式系统改由 QMS 后端拉取。

**图纸底图一起同步**：QMS 的检验页、差异对比显示真实图纸和气泡位置，不再是示例画的图。

**QMS 侧要改的地方**

| 改动 | 原因 |
|---|---|
| 收件箱按 PRD §7.2 的字段格式解析气泡 | 现在只认 QMS 内部字段 |
| 图号匹配不到零件时，可按图纸标题栏信息一键新建零件 | 新图纸才能一路走到底 |
| 标准修订保存自己的图纸底图，检验任务按快照显示对应版本的图 | 换版后旧任务仍显示旧图 |
| 集成设置预置“本机气泡软件 / Worlder 气泡图”两个地址 | 方便切换 |
| “模拟气泡推送”保留，改名为“离线演示数据” | 没启动气泡软件时还能演示 |

## 5 技术选型

| 部分 | 选型 | 理由 |
|---|---|---|
| 界面 | Vue 3 + Tailwind，和 QMS 原型同一套写法 | 风格一致，可复用组件 |
| 读 PDF、渲染页面 | pdf.js | 浏览器内运行，读得到文字坐标和旋转角度 |
| OCR | tesseract.js（WASM），本地英文 + 简体中文语言包 | 离线、无需显卡；准确度有限，见第 7 章 |
| 服务端 | Node.js 小服务，不依赖第三方包 | 静态页面 + REST 接口 + 本地 data/ 目录存图纸和 JSON，方便私有化部署 |
| 依赖文件 | 全部放在本地 vendor/，构建时从 npm 镜像下载 | 部署后不需要外网 |

## 6 怎么证明能跑通

| 测试 | 内容 |
|---|---|
| 单元测试 | 第 2 章各类写法的解析结果；GB/T 1804、ISO 286 查表（用教科书已知值核对）；换版映射；内容摘要 |
| 测试图纸 | 用程序生成 3 张样图：法兰盘、传动轴（A、B 两版，B 版改公差、加一个特性、删一个特性）、支架（扫描图）。矢量 PDF 和 PNG 各一份，预期特性清单写在测试里 |
| 端到端（无头 Chrome） | 上传 → 识别（核对数量和数值）→ 校核 → 冻结 → QMS 收件箱收到并拉取 → 新建零件 → 生成标准草稿 → 提交 → 批准 → 从模板生成方案 → 开检 → 录数 → 签名提交 → 生成报告；换版：传动轴 B 版映射正确，QMS 差异正确 |
| 回归 | QMS 原有冒烟测试、规则测试全部通过 |

## 7 原型的边界

- 扫描件 OCR 的准确率有限，靠框选识别和人工校核兜底；正式版可换成服务端 OCR 模型。
- 部分 CAD 软件导出 PDF 时，形位公差符号用的是专用字体，读出来不是标准符号，需要人工选符号。
- ISO 286 只内置常用公差带：孔 D、E、F、G、H、JS、K、M、N、P，轴 d、e、f、g、h、js、k、m、n、p，5–11 级（K、M、N、P 为 6–8 级），500 mm 以内；查表结果一律标“需核对”。
- 原型不做登录：从 QMS 打开时显示 QMS 传来的用户，单独打开时显示“本机用户”；正式版和 QMS 共用统一登录。
- 数据存在服务端本地 data/ 目录；正式版换数据库和对象存储。
