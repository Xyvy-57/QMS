# Worlder QMS 前端原型（首期）

与 Worlder 气泡图配套的私有化质量管理系统原型。首期 6 个核心模块可以实际操作，外围 9 个模块只留入口。

> **状态说明（2026-11-17）**：第一版已经构建并在浏览器里打开确认过。之后加的引导层、生产主线和生产现场（报工与良率、按机台的首件、现场看板、批次追溯、流转卡与扫码、让步放行）**还没有在真实浏览器里点过**。不过构建时会自动跑两类检查：
> - 二维码单元测试：用另写的一套解码器把生成的二维码解回原文。
> - 运行时检查：在 Node 里把每个页面在 7 种演示身份下实际渲染一遍，再走一遍报工、换刀、开首件、让步放行、追溯、扫码等动作。
>
> 这两类检查目前全部通过。只在浏览器里才执行的部分（点击、摄像头、打印版式）要用下面的浏览器测试，或者亲手点一遍。

## 一、怎么打开

| 方式 | 做法 | 适用 |
|---|---|---|
| 免构建 | 双击 `index.html` | 立刻看效果。首次需要联网加载 Tailwind、Vue、Chart.js 三个库 |
| 单文件 | `npm install && node build.mjs`，得到 `qms_pro_qms.html` | 对外分发、离线演示。所有依赖内联进一个文件 |

演示数据保存在浏览器本地（localStorage）。右上角头像菜单可以切换六种演示身份，也可以重置数据。

## 二、能演示什么

界面以**生产工单为主线**，所有岗位都围着工单走；在主线之外，再按“使用者下一步该做什么”来组织：

- **生产主线**（首页）：一张工单一条线，从左到右是：技术准备（图纸气泡 → 检验标准 → 检验方案）→ 按工序路线排列的各类检验（来料 / 首件 / 巡检 / 外协回厂 / 完工 / 出货）→ 质量放行。
  - 每个节点都写明三件事：现在什么状态、在等谁、已经等了多久。
  - 默认只看“轮到我”的工单，橙点标出轮到当前身份的节点，按钮直接做下一步；不是自己的事，可以一键切换身份继续。
  - 不合格（NCR）挂在出问题的节点上，节点变红，不合格关闭前不能放行。
  - 质量放行逐项核对：所有检验合格、不合格已关闭、没有有效的质量限制、数量对得上，由质量负责人放行。
  - 巡检按工序上的频次计算，例如“每 2 小时”“每班 1 次”，从上次巡检和这道工序最近一次首件合格中较晚的时刻算起。超时后，过程巡检节点重新变成“该巡检了”。
  - 质量门禁：首件没合格时开巡检或完工检验、完工检验没合格时开出货检验，都要先确认（试制、补录等例外留给人判断）。巡检按工序看这道工序在用机台的首件。
  - 交期两天内还没放行的工单标“交期临近”。
- **工单详情**：整条主线加每一步的明细，相当于这张工单的质量档案：
  - 检验点、检验单、报告、不合格、放行检查、物料批次、主线记录；
  - 数量与良率：投产、入库合格、不良、返工、报废、让步、待处置、在制，各工序一次合格率和直通率；
  - 按机台的首件要求。

  检验、报告、不合格页面顶部会显示“所属工单”，并标出当前处在主线的哪一步。
- **报工**：生产主管按工序报合格数、不良数（第一次报工确认投产数）。有不良必须写现象，系统自动登记 NCR。处置执行后，返工、报废、让步的数量回写到工单；数量对不上时不能放行。
  - 每道工序最多报“能到这道工序的件”，前道报废、退货的件不算在内。
  - 报错了可以在工单详情的“报工记录”里撤销，写明原因，撤销留有记录。
  - 检验已经判过的不良再在报工里报成不良，会重复登记一张不合格单；质量确认范围时填 0 件即可关闭。
  - 完工、出货检验发现的不良，按这类检验在工序路线上的位置记账：终检之后发现、报废的件从入库合格里扣。来料检验的不合格不算进工单数量，但没关闭前照样挡放行。
- **首件按机台、按事件**：
  - 每道有首件检验点的工序、每台在做的机台，各有一条首件要求。
  - 登记开工、换型、换刀、修机后、停机恢复、工艺变更后，这台机台要重新做首件；“下机”表示不再做这张工单。
  - 开班首件默认开启：上一班合格、本班还在生产的，开班后再做一次（设置里可关）。
- **现场看板**：检验员的待检队列，按紧急程度排序：巡检超时最急，其次是等首件的机台，再往后是不合格、进行中的检验、快到点的巡检。可以按产线筛选、只看自己能做的。机台卡片显示状态和下次巡检时间，生产主管在卡片上直接报工、登记换刀。
- **批次追溯**：
  - 往回查：输入发货单、成品批次或客户，查到工单、来料批次和供应商，并列出同批来料还用在哪些工单。
  - 往后查：输入来料批次或供应商，查到用了它的工单和发出去的货。
  - 一键质量限制：先登记一张 NCR，再按勾选的范围逐条建立限制。
- **工单流转卡与扫码**：A4 打印，右上角二维码。手机或平板扫码，直接进到这张工单上自己要做的检验。顶栏有扫码按钮（浏览器支持时可用摄像头）；扫码枪在任何页面都能直接扫。
- **让步放行**：工单上有让步接收时，放行要逐行填批准方（客户 / 技术）、批准文件编号、批准人，记进放行记录和工单档案，工单标“让步放行”。
- **身份流程条**：每种身份有一条自己的工作流程，从左到右排开，每一步都能点。首页是卡片版（带说明和待办数量），其它页面顶部是一行细条，当前所在的步骤高亮。步骤上的红色数字是这一步等着处理的数量，点一下直接打开第一件。
  - 检验员：看现场 → 接任务 → 录数据 → 拍照取证 → 签名提交 → 看结果
  - 质量工程师：收气泡 → 定标准 → 编方案 → 盯主线 → 处置不合格 → 看报告
  - 质量负责人：审标准 → 审方案 → 复核报告 → 批准处置 → 验证关闭 → 质量放行 → 看数据
  - 生产主管：看主线 → 报工 → 核对不合格 → 提返工建议 → 跟进处置 → 看数据
  - 仓库执行人：看质量限制 → 发货前核对 → 可发货的工单 → 查报告
  - 系统管理员：管账号 → 接气泡服务 → 查日志
  - 检验员打开一张检验后，流程条变成“这张检验的进度”：走过的步骤打勾，当前步骤显示已录数量或还差几项照片；点“录数据 / 拍照取证 / 签名提交”不会跳走，而是在当前页面定位到对应的操作。
- **工序视图**：从主线看板右上角进入。按工序路线看每张工单的检验点，点检验点就开检，颜色表示结果。
- **新建检验**：三步向导（选零件 → 选检验点 → 确认开始），顶栏随时可点。
- **下一步提示条**：标准、方案、检验、报告、NCR 页面都会说明下一步做什么、该谁做；不是当前身份的事时，可以一键切换身份继续。
- 侧栏默认只显示日常用到的几项，其余在“更多功能”里。

最快的看法：打开首页“生产主线”，点一张工单进详情，按节点上的按钮往下走；不是当前身份的事，点“切换为某某继续”。

演示数据里专门准备了几条现场场景：

| 看什么 | 怎么看 |
|---|---|
| 开班首件 | 检验员打开“现场看板”：WO-2611-011 在 CNC-04 上要做开班首件（昨天的首件合格，今天还在生产） |
| 换刀后重做首件 | 生产主管在看板的 CNC-02 卡片上点“换型 / 换刀”登记换刀；切到检验员，看板上出现“换刀后首件待检”，点“开首件” |
| 报工与良率 | WO-2611-011 详情的“数量与良率”：工序 20 报了 120 件，巡检发现 36 件不良，一次合格率 70%；生产主管点“报工”再报一次 |
| 让步放行 | 切到质量负责人，打开 WO-2611-064（交期临近），点“质量放行”：有 2 件让步接收，要填批准方、文件编号（已从处置理由带出 CC-2611-05）、批准人 |
| 往回追溯 | 打开“批次追溯”，点“发货单 DN-2611-007”：查到 WO-2611-052、来料批次和供应商恒科五金 |
| 往后追溯并隔离 | 切到质量工程师，在“批次追溯”点来料批次示例（外协回厂包装破损的那一批，用在 WO-2611-092），再点“一键质量限制” |
| 流转卡 | 任意工单详情点“流转卡”，打印预览 |

也可以按模块逐个走一遍（括号里是需要切换到的身份）：

1. **气泡识别工作台**：页面内嵌气泡软件。点“模拟气泡推送”，同步收件箱里出现一条待处理记录；“查看差异”能看到新增、变更、删除的特性。（质量工程师）“生成标准草稿”。
2. **检验标准**：核对检具和特殊特性等级后“提交审核”；（质量负责人）“批准生效”。旧版本自动停用，但引用它的方案不会被自动更换。
3. **检验方案**：方案详情出现“有新标准版本”的提示，（质量工程师）“采用新标准版本”生成新修订；也可以在“方案模板”里从模板给另一个零件生成方案。
4. **检验任务**：在任意场景点“新建任务”，或在“零部件”的工序检验点上点“发起”。建单时冻结场景、标准、方案三层快照。
5. **检验执行**：左边图纸、右边录数表格联动；超差标红，缺失不当作 0。可以试“设备导入”（生成演示报文）、拍照（没有图片时用“示例”）、手写签名提交。
6. **检验报告**：提交后自动冻结成 A4 报告。生产首件和出货检验需要复核：（质量负责人）手写签名签批，或写意见退回。可以打印成 PDF。
7. **不合格处置**：在不合格的任务上“登记不合格”→ 确认范围（可同时建立质量限制）→ 添加处置行（数量合计要等于确认不合格数量）→（质量负责人）逐行批准 →（质量工程师）登记执行 → 在原任务“发起复检”→（质量负责人）验证关闭。

其它值得看的地方：

- **检验场景与流程**：10 个可复用步骤拼出五类检验的流程，可以启停步骤、调参数、发布新版本。
- **工序路线与模板**：拖动调整工序顺序，给工序绑定检验点，一键应用到多个零件。
- **用户与角色**：权限矩阵。切到“系统管理员”后，所有批准类按钮置灰并说明原因。
- **研发排期看板**：团队内部工具，8 列对应《开发流程确定方案》的 ①–⑧，拖动卡片会校验门禁。
- `⌘K` / `Ctrl+K`：命令面板，可搜索页面、任务、标准、报告、NCR。

## 三、构建与测试

```bash
npm install                 # Tailwind CLI、puppeteer-core
node build.mjs              # 生成 qms_pro_qms.html，然后自动跑 tests/unit.mjs 和 tests/ssr.mjs（加 --skip-tests 跳过）
node tests/smoke.mjs        # 浏览器：逐个路由打开，检查无脚本错误（加 --shots shots 可截图）
node tests/e2e.mjs          # 浏览器：规则与主链、身份流程条、生产现场（真实点击）
```

构建时自动运行的两项检查不需要浏览器：
- `tests/unit.mjs`：二维码。用另写的一套解码器把生成的码解回原文，覆盖版本 1–10、四种纠错等级、八种掩模，并核对标准里的已知数值。
- `tests/ssr.mjs`：用 Vue 服务端渲染，把每个页面在每种身份下渲染一遍，模板里有没定义的名字、计算里抛异常都会报出来。同时走一遍报工、换刀、开首件、门禁、让步放行、追溯、一键质量限制、扫码。Vue 取本目录或 `../04_气泡识别软件` 的 node_modules。

浏览器测试默认测 `qms_pro_qms.html`，加 `--html index.html` 可以测免构建入口。需要本机装有 Chrome（或用环境变量 `CHROME_BIN` 指定）。

## 五、与气泡软件的对接

- 气泡软件用自研的 `../04_气泡识别软件/`：在那个目录运行 `node server.mjs`，会同时启动气泡服务（3080 端口）和 QMS（5180 端口），并自动打开 `http://localhost:5180`。运行的终端窗口不要关。
- 要内嵌气泡软件，请用 `http://localhost:5180` 打开 QMS，不要双击 HTML 文件，否则浏览器会拒绝内嵌。
- 内嵌地址在“系统 › 集成设置”里配置，默认 `http://localhost:3080`。
- 对接方式（消息通知、按批次拉取、SHA-256 校验、允许被内嵌的来源）见 PRD 第 7 章。
- 气泡服务没启动时，用“模拟气泡推送”也可以走通后面的全部流程。
- 平板、手机扫流转卡上的二维码：
  1. 用 `node server.mjs --host 0.0.0.0` 启动，终端会列出局域网地址；
  2. 把地址填到“集成设置 › 生产现场 › 扫码地址”，再打印流转卡。

  原型的演示数据存在各自设备的浏览器里，所以平板上看到的是平板自己的演示数据；正式系统的数据在服务器上，扫码后看到的是同一份。

## 六、原型的边界

- 判定、抽样、权限、签名摘要都在浏览器里模拟；正式系统必须放在服务端。
- 抽样表只内置了 GB/T 2828.1 的一个演示子集，正式使用要导入企业授权的版本。
- 内容摘要用的是演示算法，正式系统用 SHA-256；电子签名是否需要第三方 CA，由企业确认。
- 照片压缩后存在浏览器里，量大时会存满；正式系统存私有对象存储。
- 没有实现“提交后追加更正”和 Excel 报告模板的单元格映射。
- 工单、报工、收货批次、机台都在 QMS 里登记或用演示数据；正式系统有 ERP / MES / WMS 时从接口同步（PRD Q-18、Q-22）。
- 质量门禁只提示确认、不强制禁止；数量平衡要求严格相等。这两条都待企业确认（PRD Q-17、Q-19）。
