# Worlder QMS 前端原型（首期）

与 Worlder 气泡图配套的私有化质量管理系统原型。首期 6 个核心模块可以实际操作，外围 9 个模块只留入口。

> **状态说明（2026-11-16）**：第一版已经构建并在浏览器里打开确认过。之后加的引导层（身份流程条、我的工作、生产工单、新建检验向导、下一步提示条）和两个测试脚本**还没有运行验证过**（编写时所在的会话无法执行命令）。打开时如果报错，页面中央会直接显示出错的文件和行号；按“三、构建与测试”跑一遍测试可以一次性找出问题。

## 一、怎么打开

| 方式 | 做法 | 适用 |
|---|---|---|
| 免构建 | 双击 `index.html` | 立刻看效果。首次需要联网加载 Tailwind、Vue、Chart.js 三个库 |
| 单文件 | `npm install && node build.mjs`，得到 `qms_pro_qms.html` | 对外分发、离线演示。所有依赖内联进一个文件 |

演示数据保存在浏览器本地（localStorage）。右上角头像菜单可以切换六种演示身份，也可以重置数据。

## 二、能演示什么

界面按“使用者下一步该做什么”来组织：

- **身份流程条**：每种身份有一条自己的工作流程，从左到右排开，每一步都能点。首页是卡片版（带说明和待办数量），其它页面顶部是一行细条，当前所在的步骤高亮。步骤上的红色数字是这一步等着处理的数量，点一下直接打开第一件。
  - 检验员：接任务 → 录数据 → 拍照取证 → 签名提交 → 看结果
  - 质量工程师：收气泡 → 定标准 → 编方案 → 开检验 → 处置不合格 → 看报告
  - 质量负责人：审标准 → 审方案 → 复核报告 → 批准处置 → 验证关闭 → 看数据
  - 生产主管：看工单 → 核对不合格 → 提返工建议 → 跟进处置 → 看数据
  - 仓库执行人：看质量限制 → 发货前核对 → 查报告
  - 系统管理员：管账号 → 接气泡服务 → 查日志
  - 检验员打开一张检验后，流程条变成“这张检验的进度”：走过的步骤打勾，当前步骤显示已录数量或还差几项照片；点“录数据 / 拍照取证 / 签名提交”不会跳走，而是在当前页面定位到对应的操作。
- **我的工作**（首页）：身份流程卡片加待办清单，每条待办带一个动作按钮。
- **生产工单**：一张工单一条工序路线，点工序上的检验点就开检，颜色表示结果。
- **新建检验**：三步向导（选零件 → 选检验点 → 确认开始），顶栏随时可点。
- **下一步提示条**：标准、方案、检验、报告、NCR 页面都会说明下一步做什么、该谁做；不是当前身份的事时，可以一键切换身份继续。
- 侧栏默认只显示日常用到的几项，其余在“更多功能”里。

建议按这条主链走一遍（括号里是需要切换到的身份）：

1. **气泡识别工作台**：页面内嵌气泡软件。点“模拟气泡推送”，同步收件箱里出现一条待处理记录；“查看差异”能看到新增、变更、删除的特性。（质量工程师）“生成标准草稿”。
2. **检验标准**：核对检具和特殊特性等级后“提交审核”；（质量负责人）“批准生效”。旧版本自动停用，但引用它的方案不会被自动更换。
3. **检验方案**：方案详情出现“有新标准版本”的提示，（质量工程师）“采用新标准版本”生成新修订；也可以在“方案模板”里从模板给另一个零件生成方案。
4. **检验任务**：在任意场景点“新建任务”，或在“零部件”的工序检验点上点“发起”。建单时冻结场景、标准、方案三层快照。
5. **检验执行**：左边图纸、右边录数表格联动；超差标红，缺失不当作 0。可以试“设备导入”（生成演示报文）、拍照（没有图片时用“示例”）、手写签名提交。
6. **检验报告**：提交后自动冻结成 A4 报告。生产首件和出货检验需要复核：（质量负责人）手写签名签批，或写意见退回。可以打印成 PDF。
7. **不合格处置**：在不合格的任务上“登记不合格”→ 确认范围（可同时建立质量限制）→ 添加处置行（数量合计要等于确认不合格数量）→（质量负责人）逐行批准 →（质量工程师）登记执行 → 在原任务“发起复检”→（质量负责人）验证关闭。

其它值得看的地方：

- **检验场景与流程**：10 个可复用步骤拼出五类检验的流程，可以启停步骤、调参数、发布新版本。
- **工序路线与模板**：拖动调整工序顺序，给工序绑定检验点，一键应用到多个零件。
- **用户与角色**：权限矩阵。切到“系统管理员”后，所有批准类按钮置灰并说明原因。
- **研发排期看板**：团队内部工具，8 列对应《开发流程确定方案》的 ①–⑧，拖动卡片会校验门禁。
- `⌘K` / `Ctrl+K`：命令面板，可搜索页面、任务、标准、报告、NCR。

## 三、构建与测试

```bash
npm install                 # Tailwind CLI、puppeteer-core
node build.mjs              # 生成 qms_pro_qms.html；vendor/ 缺文件时自动从 npm 镜像下载
node tests/smoke.mjs        # 逐个路由打开，检查无脚本错误（加 --shots shots 可截图）
node tests/e2e.mjs          # 规则与主链：判定、抽样、复检、复核、签名、白名单、持久化、身份流程条
```

两个测试默认测 `qms_pro_qms.html`，加 `--html index.html` 可以测免构建入口。需要本机装有 Chrome（或用环境变量 `CHROME_BIN` 指定）。

## 四、目录

```
index.html            免构建的开发入口
qms_pro_qms.html      构建产物（运行 build.mjs 后生成）
build.mjs             构建脚本
tailwind.config.cjs   Tailwind 配置（颜色、阴影、缓动曲线）
styles/tailwind.css   组件类（按钮、输入框、标签、表格、录入格）
styles/app.css        过渡动效、骨架屏、气泡、签名板、A4 报告、打印
src/00_head.html      构建用的页面头
src/10_core.js        判定规则、抽样、权限、演示数据、状态与路由
src/15_actions.js     领域动作：建任务、复检、提交、复核、登记 NCR
src/20_ui.js          通用组件：弹层、图纸查看器、签名板、拍照、步骤条
src/30_pages_a.js     工作台、气泡识别工作台、检验标准、检验方案
src/40_inspect.js     任务列表、新建任务、检验执行
src/45_reports.js     报告单、报告列表与详情、报告模板
src/48_guide.js       身份流程条、我的工作（首页）、生产工单、新建检验向导、下一步提示条
src/50_ncr.js         不合格处置与质量限制
src/60_masterdata.js  零部件、工序路线与模板、检验场景与流程、检具
src/70_system.js      用户与角色、操作日志、集成设置、外围模块入口
src/80_rd.js          研发排期看板
src/90_app.js         外壳：侧栏、顶栏、命令面板、路由、气泡服务消息
tests/                冒烟测试与端到端测试
vendor/               第三方库（构建时自动下载）
```

源码文件按文件名顺序拼接在同一个作用域里，所以后面的文件可以直接用前面定义的函数和常量。页面模板是字符串，由 Vue 在浏览器里编译：模板里只能用 `src/90_app.js` 末尾登记的全局名称和组件自己返回的名称。

## 五、与气泡软件的对接

- 内嵌地址在“系统 › 集成设置”里配置，默认 `https://223.106.198.62:3080`。
- 这个地址目前是自签名证书，浏览器会拦截内嵌页：先点“新窗口打开”信任证书，再回来点“刷新”。
- 气泡软件需要配合的事项（证书、允许被内嵌、统一登录、消息通知、同步接口）列在“集成设置”页和 PRD 第 7 章。
- 对方没接入之前，用“模拟气泡推送”可以走通后面的全部流程。

## 六、原型的边界

- 判定、抽样、权限、签名摘要都在浏览器里模拟；正式系统必须放在服务端。
- 抽样表只内置了 GB/T 2828.1 的一个演示子集，正式使用要导入企业授权的版本。
- 内容摘要用的是演示算法，正式系统用 SHA-256；电子签名是否需要第三方 CA，由企业确认。
- 照片压缩后存在浏览器里，量大时会存满；正式系统存私有对象存储。
- 没有实现“提交后追加更正”和 Excel 报告模板的单元格映射。
