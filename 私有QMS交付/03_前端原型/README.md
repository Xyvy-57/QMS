# Worlder QMS 前端原型（首期）

与 Worlder 气泡图配套的私有化质量管理系统原型。首期 6 个核心模块可以实际操作，外围 9 个模块只留入口。

> **状态（2026-11-20，车间作业版）**。已验证 75 个路由与身份组合、46 项端到端检查，以及手机视口下的逐项审批、分批交检、质量限制和检验续做。测试使用临时浏览器数据，不覆盖使用者的数据。手机视口测试不等于真机摄像头、扫码枪、打印机或车间用户试用。

## 给演示人员的交付包

把[工单实操演示 ZIP](demo/Worlder-QMS-工单实操演示.zip) 发给演示人员。解压后在电脑浏览器打开「开始演示.html」，即进入可填写读数的精车巡检。另一份「演示讲解卡.html」可打印为一页。电脑右上角可切换手机视图，演示人员可以在同一张工单上完成逐项审批、报工、分批交检和质量放行。「重新演示」支持从登记工单开始。

在本目录运行 `npm run delivery` 重新生成交付包，运行 `npm run test:delivery` 从压缩包解压并断网走通桌面及手机尺寸的两条实操流程。

## 工单双端演示

打开工作台的「Web 端演示」或「手机端演示」，也可以单独带走[离线工单演示](demo/工单操作演示.html)。同一张 `WO-DEMO-208` 工单覆盖登记、五类检验、异常处置、复检、分批交检和质量放行。两个视口分别采集了 18 个操作画面。

点画面里的黄色操作框逐步体验，或者点「自动演示」。章节和步骤可以直接跳转，切换端时保留当前位置。「动手练习」提供巡检录数、逐项审批和分批交检三个工位场景。练习直接在 QMS 表单中进行，进度单独保存在当前标签页。点「重做本项」可回到该项练习的起点。

## 二、能演示什么

**新用户的三条试用路径**（不同岗位在同一浏览器的头像菜单中切换）：

| 岗位与场景 | 操作 | 可以核对的结果 |
|---|---|---|
| 检验员接任务 | 首页找到 `WO-2611-011` 的 CNC-04 首件，点「开首件」；手机先录数，需要时展开图纸。点「返回工单」。 | 不重选工单、工序或机台，返回时定位首件节点。 |
| 生产主管报出不良 | 查 `WO-2611-011`，在「20 精车」点「报工」，填合格 2、不良 1，并描述现象。 | 回执显示两类数量，可打开本笔不合格单。刷新回执不重复入账；回执也可从「记录」重新打开。 |
| 换刀后交检 | 生产主管查 `WO-2611-021`，在「工序作业」登记 CNC-02 换刀；检验员从待办或本次回执开首件。 | 新首件自动带出原工单、工序、机台和换刀原因；回到回执可以看原单，不重复开单。 |

**试用分批出货**。在工单里查找 `WO-DEMO-072`，切换为检验员，点「开下一批出货检验」。页面显示入库合格 298 件、已安排交检 100 件、剩余 198 件。填写这次发货的实际件数，核对成品批次后点「确认开检」。每个检验批只计一次，复检沿用原单。完工交检取本笔终检报工的合格件数，有多笔报工时可以选择。

**试用逐项审批**。质量负责人打开 `NCR-2026-0012`，在手机上点「定位操作」。分别查看「返工 30 件」和「报废 6 件」，只批准报废即可看到这一项的接手岗位。返回 `WO-2611-011`，工单顶部逐条列出限制动作、对象和依据。

**试用检验续做**。检验员打开 `WO-2611-021` 的来料检验，在逐项模式选择第 4 项「支撑杆高」和一个样本，回工单再点「继续检验」。浏览器恢复当前检验员在本轮选中的样本，底部「去录入」仍可定位到第一个缺项。

界面实拍：[岗位待办](qa/车间作业版/01-检验员待办.png) · [手机工单](qa/车间作业版/02-手机工单.png) · [手机录数](qa/车间作业版/03-手机录数.png) · [报工交接](qa/车间作业版/04-工序交接.png) · [逐项审批](qa/车间作业版/05-手机逐项审批.png) · [分批交检](qa/车间作业版/06-出货分批交检.png)。

设计参照：黑湖小工单的[流转卡与移动报工](https://www.xiaogongdan.cn/products)，以及开源 ERPNext 的[工序作业卡](https://docs.frappe.io/erpnext/job-card)。借鉴的是业务组织方式，没有引入这两套系统或新增运行依赖。

- **侧栏只有五个日常入口**：首页、工单、检验、不合格、报告。质量工程师和质量负责人多一组“图纸与标准”（气泡识别、检验标准、检验方案）；现场看板、批次追溯、基础资料、系统设置都在“更多功能”里。角标只在“首页”上，数字就是首页待办的条数。
- **顶栏只有扫码和身份**。去掉了每页顶部的流程条、待办铃铛、“新建检验”按钮和搜索框：待办都在首页，查找在首页和各列表页（`⌘K` 仍可用）。
- **首页：我的待办**。
  - 先看班次、岗位和待办总数；按工单归拢，不能唯一归属的事项保留在「公共待办」，不猜测属于哪张单。旁边的「车间需关注」不计入个人待办。
  - 当前岗位的步骤从左到右排列，有待办才显示数量；点有待办的步骤筛选，其他步骤打开对应工作面。
  - 每条待办一句话说清做什么、在哪，右边一个按钮直达：开首件、继续录数据、去审批、质量放行……
  - 同一件事只出现一次。
  - 各身份的流程：
    - 检验员：现场到点 → 接任务 → 录数据 → 拍照取证 → 签名提交 → 看结果
    - 质量工程师：收气泡 → 定标准 → 编方案 → 盯工单 → 处置不合格 → 看报告
    - 质量负责人：审标准 → 审方案 → 复核报告 → 批准处置 → 验证关闭 → 质量放行 → 看数据
    - 生产主管：看工单 → 报工 → 核对不合格 → 提返工建议 → 跟进处置 → 看数据
    - 仓库执行人：看质量限制 → 发货前核对 → 可发货的工单 → 查报告
    - 系统管理员：管账号 → 接气泡服务 → 查日志
- **工单列表**：桌面按列比较，手机分行显示当前环节、接手人和异常，不用横滑。首页输入完整工单号打开工单，扫码仍优先进入本人要做的检验。按「轮到我」也能找到待报工的工单。
- **登记工单**：工单号自动建议、可修改；选择生产零件，填写计划数量，就可以建单。交期和物料批次选填，不预填示例产品或产量。
- **工单视觉提示**：主线节点用图标和状态标识区分当前、等待、受阻和完成。「定位工序」聚焦对应检验点；「放行条件」优先显示有效限制和未关闭的不合格，可直接到对应记录。
- **工单详情**，从上到下一页看完：
  - 现在该做什么：只有一个主按钮，不是你的事就说明在等谁、已经等了多久。
  - 主线：技术准备 → 各类检验 → 质量放行，点节点看说明。
  - 工序：每道工序一行，写着报了多少、合格率；这道工序上的检验点一下就开检或打开。
  - 不合格：有才显示。
  - 放行检查：可从工单顶部打开，优先列出未通过项；进入放行时也会显示。
  - 记录：默认收起。

  流转卡、物料批次和报工记录（可撤销）在右上角「更多」；换型 / 换刀在「工序作业」。
- **检验页**：显示录入、拍照和签名进度，并框出当前待录入或待修正的字段。底部主按钮定位到下一格或打开对应特性的拍照；预览报告、设备导入、有缺项时提前提交仍在“更多”里。
- **报告页**：打开就是报告本身；签名校验、关联对象、照片收在下面的“详情”里。
- **标准、方案、不合格页**：去掉了重复说明状态的步骤条。“下一步”提示只在还有事要做时出现。
- 业务规则不变：
  - 报工与数量台账、首件按机台与换型触发、巡检到点、质量门禁；
  - 让步放行要填批准依据；
  - 批次追溯与一键质量限制；
  - 流转卡二维码与扫码枪。

最快的看法：打开首页，点第一条待办的按钮；不是当前身份的事，工单详情里点“切换为某某继续”。

演示数据里专门准备了几条现场场景：

| 看什么 | 怎么看 |
|---|---|
| 开班首件 | 切到检验员，首页第一条就是“开班首件待检 · CNC-04”（WO-2611-011 昨天的首件合格，今天还在生产），点“开首件” |
| 换刀后重做首件 | 生产主管打开 WO-2611-021，在「工序作业 › 登记换型 / 换刀」登记 CNC-02 换刀；检验员在待办或回执开首件 |
| 报工与良率 | WO-2611-011 详情的「工序作业」：工序 20 报了 120 件，巡检发现 36 件不良，一次合格率 70%；生产主管点该行「报工」再报一次 |
| 让步放行 | 切到质量负责人，打开 WO-2611-064（交期临近），点“质量放行”：有 2 件让步接收，要填批准方、文件编号（已从处置理由带出 CC-2611-05）、批准人 |
| 往回追溯 | 在“更多功能 › 批次追溯”里点“发货单 DN-2611-007”：查到 WO-2611-052、来料批次和供应商恒科五金 |
| 往后追溯并隔离 | 切到质量工程师，在“批次追溯”点来料批次示例（外协回厂包装破损的那一批，用在 WO-2611-092），再点“一键质量限制” |
| 流转卡 | 任意工单详情右上角“更多 › 打印流转卡” |

也可以按模块逐个走一遍（括号里是需要切换到的身份）：

1. **气泡识别工作台**：页面内嵌气泡软件。点“模拟气泡推送”，同步收件箱里出现一条待处理记录；“查看差异”能看到新增、变更、删除的特性。（质量工程师）“生成标准草稿”。
2. **检验标准**：核对检具和特殊特性等级后“提交审核”；（质量负责人）“批准生效”。旧版本自动停用，但引用它的方案不会被自动更换。
3. **检验方案**：方案详情出现“有新标准版本”的提示，（质量工程师）“采用新标准版本”生成新修订；也可以在“方案模板”里从模板给另一个零件生成方案。
4. **检验任务**：在任意场景点“新建任务”，或在“零部件”的工序检验点上点“发起”。建单时冻结场景、标准、方案三层快照。
5. **检验执行**：左边图纸、右边录数表格联动；超差标红，缺失不当作 0。可以试“设备导入”（生成演示报文）、拍照（没有图片时用“示例”）、手写签名提交。
6. **检验报告**：提交后自动冻结成 A4 报告。生产首件和出货检验需要复核：（质量负责人）手写签名签批，或写意见退回。可以打印成 PDF。
7. **不合格处置**：在不合格的任务上“登记不合格”→ 确认范围（可同时建立质量限制）→ 添加处置行（数量合计要等于确认不合格数量）→（质量负责人）逐行批准 →（质量工程师）登记执行 → 在原任务“发起复检”→（质量负责人）验证关闭。

其它值得看的地方：

- **检验场景与流程**：10 个可复用步骤拼出五类检验的流程，可以启停步骤、调参数、发布新版本。
- **工序路线与模板**：拖动调整工序顺序，给工序绑定检验点，一键应用到多个零件。
- **用户与角色**：权限矩阵。切到“系统管理员”后，所有批准类按钮置灰并说明原因。
- **研发排期看板**：团队内部工具，8 列对应《开发流程确定方案》的 ①–⑧，拖动卡片会校验门禁。
- `⌘K` / `Ctrl+K`：命令面板，可搜索页面、任务、标准、报告、NCR。

## 三、构建与测试

```bash
npm install                 # Tailwind CLI、puppeteer-core
node build.mjs              # 生成 qms_pro_qms.html，然后自动跑 tests/unit.mjs 和 tests/ssr.mjs（加 --skip-tests 跳过）
node tests/smoke.mjs        # 浏览器：逐个路由打开，检查无脚本错误（加 --shots shots 可截图）
node tests/e2e.mjs          # 浏览器：规则与主链、身份流程条、生产现场（真实点击）
node tests/workflow.mjs     # 手机宽度：待办与回跳、不良报工回执、换刀后首件交接、新建工单
node tests/visual-cues.mjs  # 放行阻塞入口、工序和表单焦点、计数纠错、拍照到签名
node --test tests/shop-interactions.mjs  # 逐项审批、限制范围、样本续做和分批交检边界
node --test tests/order-tour.mjs         # 两端逐步跟点、播放控制、单文件离线与实操隔离
node build.mjs --tour-out demo/工单操作演示.html  # 同时生成直接进入导览的离线文件
```

构建时自动运行的两项检查不需要浏览器：
- `tests/unit.mjs`：二维码。用另写的一套解码器把生成的码解回原文，覆盖版本 1–10、四种纠错等级、八种掩模，并核对标准里的已知数值。
- `tests/ssr.mjs`：用 Vue 服务端渲染，把每个页面在每种身份下渲染一遍，模板里有没定义的名字、计算里抛异常都会报出来。同时走一遍报工、换刀、开首件、门禁、让步放行、追溯、一键质量限制、扫码。Vue 取本目录或 `../04_气泡识别软件` 的 node_modules。

浏览器测试默认测 `qms_pro_qms.html`，加 `--html index.html` 可以测免构建入口。需要本机装有 Chrome（或用环境变量 `CHROME_BIN` 指定）。

## 五、与气泡软件的对接

- 气泡软件用自研的 `../04_气泡识别软件/`：在那个目录运行 `node server.mjs`，会同时启动气泡服务（3080 端口）和 QMS（5180 端口），并自动打开 `http://localhost:5180`。运行的终端窗口不要关。
- 要内嵌气泡软件，请用 `http://localhost:5180` 打开 QMS，不要双击 HTML 文件，否则浏览器会拒绝内嵌。
- 内嵌地址在“系统 › 集成设置”里配置，默认 `http://localhost:3080`。
- 对接方式（消息通知、按批次拉取、SHA-256 校验、允许被内嵌的来源）见 PRD 第 7 章。
- 气泡服务没启动时，用“模拟气泡推送”也可以走通后面的全部流程。
- 平板、手机扫流转卡上的二维码：
  1. 用 `node server.mjs --host 0.0.0.0` 启动，终端会列出局域网地址；
  2. 把地址填到“集成设置 › 生产现场 › 扫码地址”，再打印流转卡。

  原型的演示数据存在各自设备的浏览器里，所以平板上看到的是平板自己的演示数据；正式系统的数据在服务器上，扫码后看到的是同一份。

## 六、原型的边界

- 判定、抽样、权限、签名摘要都在浏览器里模拟；正式系统必须放在服务端。
- 抽样表只内置了 GB/T 2828.1 的一个演示子集，正式使用要导入企业授权的版本。
- 内容摘要用的是演示算法，正式系统用 SHA-256；电子签名是否需要第三方 CA，由企业确认。
- 照片压缩后存在浏览器里，量大时会存满；正式系统存私有对象存储。
- 没有实现“提交后追加更正”和 Excel 报告模板的单元格映射。
- 工单、报工、收货批次、机台都在 QMS 里登记或用演示数据；正式系统有 ERP / MES / WMS 时从接口同步（PRD Q-18、Q-22）。
- 质量门禁只提示确认、不强制禁止；数量平衡要求严格相等。这两条都待企业确认（PRD Q-17、Q-19）。
